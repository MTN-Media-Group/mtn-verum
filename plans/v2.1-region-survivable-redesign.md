# Plan v2.1: `mtn-verum` v1 format - region-survivable, rotation-invariant, key-secure watermarking

> **Supersedes [v2-region-survivable-redesign.md](v2-region-survivable-redesign.md)** (2026-08-14).
> v2 was rejected in review for four structural flaw classes: a payload layer that
> was not translation-invariant, a dense tiled carrier whose Fourier-Mellin
> correlation is not mathematically valid after arbitrary rotation/scale, a
> capacity table that ignored its own bin partition, and security claims that
> were not supported by the construction. This document replaces v2 in full.
>
> **Revision: v2.1-r8** (2026-08-14): all three owner decisions resolved. Adds
> **attested frames** - BLS-signed, publicly verifiable without the embed secret -
> at owner request, alongside the existing compact HMAC frame.

## Context and supersession rationale

The current `mtn-verum` codebase implements a tile-grid-locked DCT-coefficient-pair
scheme. It survives top-left crops up to a small tile-period offset, JPEG Q95 in
the robust path, and a limited set of downscales. It does not satisfy the actual
requirement: a marked region cropped out, rotated, scaled, and pasted into another
image should still identify as MTN-generated when enough source support remains.
Nothing has shipped, so the on-image format, public result fields, package
constants and `PayloadVersion` reset cleanly.

v2 proposed the right layering - keyed carrier for local synchronization,
Fourier-Mellin pose recovery, spread payload, windowed aggregation, MAC-gated
detection. Review of v2 found the instantiation wrong in four ways:

1. **Translation.** An arbitrary crop retains an unknown cyclic offset
   `τ = (τx, τy)` against the periodic tile, so a canonical data coefficient is
   observed as `Z_k = e^(-j2πk·τ/P) D_k + H_k`. A sign/correlation statistic over
   such coefficients depends on `τ` and averages to zero over arbitrary crop
   phase, and the FFT-magnitude step in pose recovery discards exactly the
   information needed to undo it. v2 named the risk and did not resolve it.
2. **Carrier validity.** Correlating a window against one dense 50%-occupancy
   tiled template is valid only for axis-aligned integer-shift `P×P` crops; under
   arbitrary rotation, scale, taper and off-grid resampling the window spectrum
   carries translation-dependent cross terms wherever lobes overlap, which at 50%
   occupancy is everywhere. And since
   `|Y_k|² = |X_k|² + α²|C_k|² + 2α·Re{X_k C_k*}`, at invisible strength the host
   cross term dominates the `α²|C_k|²` signature the detector assumed it saw.
3. **Capacity.** The v2 table counted the whole annulus while the design gave
   data only 40% of it, and stacked `K`-chip repetition on top of ECC. Correct
   enumeration shows no patch size carries the v2 frame as specified.
4. **Security.** A tenant-wide fixed carrier is a reusable removal template
   recoverable by corpus averaging; a frame MAC over frame bytes alone permits
   transplanting a valid residual onto unrelated pixels; and the v2 result struct
   is an efficient watermark-removal oracle.

v2.1 keeps the layering and replaces the instantiation. It also introduces a
mandatory Phase 0 feasibility spike: whether a carrier held under SSIM ≥ 0.995
survives Q75 plus rotation plus downscale inside a 192 px window decides whether
the approach is viable at all, and v2 deferred that question to Phase 6.

The design stays clean-room and uses only established public watermarking,
cryptographic, and signal-processing literature:

- Cox, Kilian, Leighton, and Shamoon, "Secure Spread Spectrum Watermarking for
  Multimedia," IEEE Transactions on Image Processing, 1997.
- Ó Ruanaidh and Pun, "Rotation, Scale and Translation Invariant Digital Image
  Watermarking," Signal Processing, 1998.
- Pereira, Ó Ruanaidh, Deguillaume, Csurka, and Pun, "Template Based Recovery of
  Fourier-Based Watermarks Using Log-Polar and Log-Log Maps," IEEE ICMCS, 1999.
- Pereira and Pun, "Robust Template Matching for Affine Resistant Image
  Watermarks," IEEE Transactions on Image Processing, 2000.
- Lin, Wu, Bloom, Cox, Miller, and Lui, "Rotation, Scale, and Translation
  Resilient Watermarking for Images," IEEE Transactions on Image Processing,
  2001.
- Chen and Wornell, "Quantization Index Modulation," IEEE Transactions on
  Information Theory, 2001.
- Moulin and Malvar, "Detection-Theoretic Analysis of Desynchronization Attacks
  in Watermarking," MSR-TR-2002-24, 2002.
- Petitcolas, Anderson, and Kuhn, StirMark robustness benchmarking work.
- Craver, Memon, Yeo, and Yeung, "Resolving Rightful Ownerships with Invisible
  Watermarking Techniques," 1998.
- Kutter, Voloshynovskiy, and Herrigel, watermark copy-attack work.
- NIST FIPS 198-1 HMAC, NIST SP 800-90A HMAC-DRBG, and RFC 5869 HKDF.

**What the literature does and does not support.** These citations substantiate the
*constructions* - spread-spectrum embedding, log-polar pose recovery, DFT template
matching, QIM, desynchronization analysis - not the capacity point v2.1 is aiming
at. The strongest cited blind RST-resilient demonstrations carry on the order of
one presence bit to ~100 bits in 512² images at higher visibility budgets. v2.1
targets ~200 raw bits in a 192² window, blind, under full RST, Q75 and
SSIM ≥ 0.995: roughly 14× the payload density per pixel of the strongest cited
blind-RST result. No published work demonstrates that operating point. Phase 0 is
the arbiter, and the Phase 0 escalation path already covers retreat to a
presence-token or whole-image design if the density is unreachable.

## User-confirmed parameters

- **Minimum surviving region size**: `Config.MinPatchSize`. The original user
  confirmation listed 128 / 192 / 256 px, default 192. **v2.1 supports 192 / 256
  only; removal of 128 is ✅ approved by owner 2026-08-14.** The reasoning that was
  approved is retained in the "P=128 (removed)" subsection - guard overhead above
  58%, a reduced frame that violated the evidence model, and rate-1/2-only
  fragility - together with what reopening it would require. Smaller values reduce
  the detectable patch floor but weaken JPEG/denoise margin and raise visibility
  risk.
- **Visibility budget at strongest profile**: SSIM ≥ 0.995, PSNR ≥ 44 on the
  calibration corpus. At maximum strength, artifacts may still be perceptible to
  expert viewers in smooth regions.
- **JPEG floor**: Q75. `StrengthBalanced` and `StrengthRobust` must demonstrate
  Q75 transcode survival in the calibration corpus.
- **Legacy compatibility**: none. `PayloadVersion` is exactly `1`. The
  pre-release tile-grid format is abandoned completely; README / NOTICE /
  CHANGELOG must say so.
- **Implementation constraint**: pure Go; no CGO dependency for lossy WebP.
- **Licensing posture**: AGPL source, keyed security. The attacker knows the
  algorithm, carrier band, code, and all public parameters.
- **Public verifiability**: verifying a mark must not require the secret that
  embeds it, and **server-side content binding is rejected** - detection and
  verification must run standalone with no MTN service. Owner requirement,
  2026-08-14. Satisfied by the attested frame type.
- **Verification-bundle distribution posture** ✅ **owner selected: Public,
  2026-08-14**. The verification bundle is published and anyone can verify any
  image fully offline. The costs accepted with that choice, kept here as the record
  of what was approved: the removal skill floor drops from "implements the fold
  attack" to "runs the published tool in a loop" (an already-accepted exposure),
  and replay synthesis becomes clean - a bundle holder can re-embed an observed
  signed token into another image at full strength with no residual estimation.
  Neither cost touches minting: no posture lets a bundle holder create a new signed
  token. Private and Partner remain documented in the attested-frames section as
  fallback configurations MTN can revert to operationally, since bundle
  distribution is policy rather than format - reverting changes no bits on the
  image. Private notably does **not** satisfy the public-verifiability requirement
  above, which is why it is a fallback and not an alternative.
- **Detection-resistance posture** ✅ **accepted by owner 2026-08-14**: v2
  claimed "stripping requires the tenant secret". v2.1 does not. The honest
  posture is "stripping is cheap for a determined single-image attacker; the
  value delivered is forgery resistance plus detection of unmodified and
  casually-transformed images". See the fold-and-null discussion in Security
  claims. This is a material reduction from what was originally confirmed and is
  flagged as a scope change, not absorbed silently.

## Evidence model

This section is normative and precedes the architecture because it bounds what
the architecture is allowed to claim.

A detection result bears on three distinct statements. **The system can supply two
of them, and standalone watermark verification supplies only the first:**

1. **Token presence.** A valid MTN-issued token, authenticated under signal
   epoch `E` and the frame authenticator - a MAC under frame key `K`, or a BLS
   signature under signing generation `g` - is present in these pixels. *Supplied
   by the watermark.* To any third party the token is an **opaque identifier**: the
   authenticator proves MTN issued it, not what it was issued for.
2. **Token provenance.** That token was issued for asset `X`. *Supplied by an
   MTN-internal lookup keyed on the 96-bit token, not by the image and not by
   standalone verification.* A third party running the public verifier learns claim
   1 and nothing else.
3. **Pixel provenance.** These pixels derive from asset `X`. **Not supplied by
   the watermark, and not supplied by anything else in this system.** Server-side
   content binding - comparing suspect pixels against a stored thumbnail or robust
   descriptor from the issuance record - was **rejected by the owner**: detection
   and verification must work standalone, with no MTN service in the loop. Claim 3
   is therefore permanently out of scope here. An external provenance chain such as
   C2PA could supply it, but that is a different mechanism, not this one.

Copy and replay are acknowledged, not defended against at the format layer: an
attacker who extracts the watermark residual from a marked image A and adds it to
an unrelated image B produces a B that satisfies (1) and (2) with A's token.
Nothing in the frame binds the authenticator to B's content, and a content-bound
authenticator is not achievable for a mark that must survive rotation, rescaling
and recompression. **This is unchanged for attested frames**: a BLS signature
travels with the residual exactly as the HMAC does, so a transplanted attested mark
still validates as the original token on foreign pixels. Public verifiability
changes who can *check* a token, never what the token *means*.

**Under the selected Public posture this gets sharper rather than milder**, and it
applies to everyone rather than to named parties. A bundle holder - which is now
anyone - does not need to estimate a residual: it can decode a valid
signed token from one image and **freshly re-embed it into another at full
strength**, with no SNR penalty at all. Clean replay synthesis is available to
every verification party, which now means every party. That is consistent with the
accepted transplant posture,
and it is exactly why a validating mark proves token issuance and never image
provenance.

Consequences that bind every other section:

- **MTN-internal** surfaces, which can perform the token lookup, phrase results as
  "carries an MTN AI generation token issued for asset X" - never "was generated by
  MTN AI" and never "is this asset". **Third-party and standalone-verifier surfaces
  cannot say "for asset X" at all**, because the lookup is not available to them;
  they say "carries a valid MTN-issued token".
- Pixel provenance cannot be asserted by any part of this system. There is no
  fallback comparison to run: content binding is rejected by owner decision and
  verification is fully standalone.
- `TestCopyAttackReplay` verifies the replay behaviour rather than asserting it
  fails, and NOTICE documents it.
- **A negative result is not clearance.** Absence of a detected token is *not*
  evidence that an image was not MTN-generated. Removal is cheap and keyless (see
  the fold-and-null discussion), the mark may never have been embeddable in the
  surviving region, or the region may be too small. Product surfaces must phrase a
  negative as "no MTN token found", never as "not AI-generated" or "verified
  clean". This constrains UI copy as strictly as the positive direction does.

## Architecture

### 1. Carrier: sparse guarded sync constellation

The carrier is a keyed sparse constellation, **additive with keyed complex
phase**, synthesized as one `P×P` tile.

```
constellation = S keyed conjugate peak pairs; S = 48 at P=192, 64 at P=256
placement     = 4 equal-area radial bands of the mid-frequency annulus
band edges    = 0.080000 / 0.130000 / 0.165529 / 0.194679 / 0.220000 cycles/pixel
amplitude     = keyed per bin, scaled by the embed peak-amplitude parameter a_e
phase         = keyed per bin from constKey via HMAC-DRBG
separation    = enforced minimum angular and radial spacing between peaks
asymmetry     = enforced angular asymmetry of the keyed positions
halos         = no data bin within the guard radius of any sync peak
```

The annulus target is `[0.08, 0.22]` cycles/pixel, split into four equal-area
radial bands by `r_i² = 0.0064 + i·0.0105`, giving the edges above; the three
interior edges are normative to six decimals. Equal *area* does not mean equal
enumerated bin count on the integer lattice: at P=192 the four bands hold
**596 / 616 / 612 / 612** conjugate pairs (2,436 total). The capacity budget uses
these counts, not an equal-count idealization.

Peak placement is keyed but constrained. Minimum separation keeps guard halos
disjoint. Enforced angular asymmetry kills the 90°/180° rotational aliases a
square-periodic dense carrier suffers; the centrosymmetric ambiguity inherent to
the magnitude of a real image remains and is resolved by frame validation. Band 4
peaks additionally carry a radial placement constraint: at P=192 and P=256 they
are drawn from the inner two-thirds of band 4, so the outermost bins - the first
casualties of downscale and JPEG - are not load-bearing for pose.

**Why keyed phase.** The carrier is added, not magnitude-driven. The keyed
complex phase is what makes the pilots observable: after alignment, detection and
τ-recovery correlate the window's **complex** spectrum against the known complex
template - a coherent matched filter with `√S` processing gain across pilots.
FFT-magnitude log-polar correlation is used **only** to generate coarse `(θ, s)`
hypotheses, where the statistic integrates all `S` peaks and its output SNR is a
named Phase 0 measurement rather than an assumption. This is the single coherent
construction for the whole design; there is no separate magnitude-drive embedder.

The dense tiled carrier from v2 survives only as Phase 0 comparison arm (b).

**Pilot power budget.** Translation accuracy is set by pilot SNR, and the
requirement follows from the τ target rather than from taste. For `S` uniformly
distributed pilots at per-pilot complex SNR `ρ`, the per-axis translation
estimator standard deviation is bounded below by

```
σ_τx ≥ (0.120 / √ρ) · √(64/S)  px
```

Joint `±0.5 px` on both axes at 95% needs `σ_τx ≤ 0.2236 px` per axis. At the
S=64 reference that gives `ρ ≥ 0.288` (**−5.4 dB**); at the **S = 48** used at
P=192 it tightens to `ρ ≥ 0.384` (**−4.2 dB**). Whether textured windows reach
−4.2 dB per pilot at the visibility budget is a **named Phase 0 go/no-go
measurement**. If they do not, Phase 0 arm (a') noncoherent fallback applies,
with its own halved capacity accounting in the capacity budget.

Raising `S` back to 64 at P=192 would relax the gate by 1.2 dB, and the design
deliberately does not do that: `S = 48` is what makes the conservative-halo
capacity fit work at all, so the capacity constraint is structural while 1.2 dB of
pilot SNR is marginal - and arm (a') exists precisely to absorb a τ-gate miss.

**Guard halo radius** is set by leakage physics. A separable Hann taper on a `P`
window has a ±2-bin mainlobe in each axis. Pose error contributes far less: at the
section-2 accuracy targets, `|δθ| = 0.34°` at the P=192 outer radius of 42 bins
displaces a bin by `42 × 0.0059 = 0.25` bins, and `|δs/s| = 0.6%` displaces it by
`42 × 0.006 = 0.25` bins. Two halo geometries bracket the real cost and both are
carried through the capacity budget: a **circular r=2 disk** (12.57 → 13 pairs per
peak, optimistic) and a **square ±2 guard** (5×5 = 25 pairs per peak,
conservative, matching the separable mainlobe exactly). The binding number is a
Phase 0/1 measurement; the design is sized so the conservative bound fits.

### 2. Pose and translation recovery

Rotation and scale come from Fourier-Mellin; translation is then recovered
explicitly. v2's omission of the third step is the reason its data layer could
not decode.

Per candidate window:

1. Extract luminance, apply a 2D Hann taper.
2. `W = |FFT(window)|`; magnitude removes translation phase.
3. Log-polar resample `W`, phase-correlate against the keyed constellation
   magnitude template. This step is **coarse hypothesis generation only**.
4. Estimate `(θ, s)` from the primary peak with subpixel refinement; score by
   primary/secondary peak ratio.
5. Warp the window to canonical pose.
6. **Recover `τ mod P`** by normalized cross-power phase correlation of the
   window's **complex** spectrum against the known complex pilot template at the
   known pilot positions (≈2.0 ms measured). Because the pilot phase is keyed and
   known, this is one coherent correlation, not a search.
7. **Jointly refine `(θ, s, τ)`** by maximizing the coherent keyed pilot
   likelihood - the complex matched filter of step 6 - with a bounded
   Gauss-Newton step.

Steps 6-7 are the only place the detector claims processing gain: the coherent
matched filter over `S` pilots yields `√S` amplitude gain. Step 3's magnitude
statistic discards phase and is correspondingly weaker, which is why it generates
hypotheses rather than decisions.

Accuracy targets, set by the phase sensitivity of the data layer at the P=192
outer band radius of 42 bins:

- `|δθ| ≤ 0.34°` (0.25-bin displacement at r = 42)
- `|δs/s| ≤ 0.6%` (0.25-bin displacement at r = 42)
- `|δτ| ≤ 0.5 px` per axis; 1 px of residual translation at 0.22 cycles/pixel is
  79° of phase error, which is why sub-pixel `τ` is mandatory rather than
  optional.

Ambiguity branches evaluated: the centrosymmetric 180° branch (unavoidable), plus
square-window artifact peaks and host-spectrum peaks screened by the peak-ratio
score. Constellation angular asymmetry removes the 90° family; a test asserts it.

**Data layer, default arm:** coherent spread decoding after `(θ, s, τ)`
alignment. Each usable data bin pair carries one soft coded symbol.

**Data layer, fallback arm (Phase 0, arm a'):** noncoherent modulation -
differential energy between paired bins at equal radius, or magnitude-QIM in
guarded bins. It halves symbol capacity and is weaker under JPEG, but it is
immune to residual `τ` error and does not need the −4.2 dB pilot SNR. Phase 0
measures both. If the fallback ships, the capacity budget's fallback row governs
and the support and claims sections shrink accordingly: at P=192 it carries a
single rate-1/3 codeword spread across all four bands with 18 symbols spare, so
there is no repeat copy and no 0.5x claim.

### 3. Frame and error-correcting code

```
header        1 byte   (version 4 bits ‖ flags 4 bits)
payloadToken 12 bytes  (96-bit opaque HMAC-derived identifier)
frameMAC     12 bytes  (96-bit truncated HMAC over header ‖ payloadToken ‖ context)
                       total: 200 raw bits
```

No CRC. The MAC arbitrates misdecodes; a CRC adds two bytes of capacity cost and
zero adversarial value because it is computable by anyone.

The 96-bit `payloadToken` is opaque. Full payload resolution - provider, model,
generation ID, attachment ID, timestamp - happens server-side against the
issuance record. The image does not carry them, and the external `KeyID` and
`EpochID` are inferred from which configured key and epoch validate the MAC
rather than spending capacity on them.

**MAC length derivation.** Union bound over all MAC checks a lifetime performs:
`P_false ≈ q · L / 2^t` where `q = W · B · K · E · D` is windows × pose branches ×
frame keys × epoch hypotheses × detections, and `L` is the ECC candidate-list
length. Soft Viterbi returns a **single** survivor, so `L = 1`; if list decoding
is ever added, `L` multiplies `q` and this derivation must be redone.

The key counts are enforced, not assumed: `Config.validate` caps the total tried
frame-key set `|{ActiveKey} ∪ DetectionKeys| ≤ 16` and `len(SignalKeys) ≤ 8`, so
the worst case is bounded by construction. This derivation covers **compact frames
only**; attested frames have no `frameMACKey` and are bounded instead by signature
verification, priced in § 3b.

- Forensic-sweep worst case per image: `W = 3,600`, `B = 2`, `E = 8`, and `K = 16`
  where `K` is the **total tried** frame-key set `|{ActiveKey} ∪ DetectionKeys|`
  → 921,600 MAC checks.
- Lifetime detections `D = 10^7` → `9.22 × 10^12`.
- Adversary submitting 10^3 crafted detections/day for 10 years adds
  `3.65 × 10^6 × 921,600 = 3.36 × 10^12`.
- Total lifetime trial budget `q ≈ 1.26 × 10^13 ≈ 2^43.5`.

Target `ε ≤ 10^-12 ≈ 2^-39.9`. Then `t ≥ ⌈log₂(q/ε)⌉ = ⌈43.5 + 39.9⌉ = 84` bits.
**96 bits** is chosen: 12 bits of headroom against growth in `q` even at the
enforced caps. For contrast, a 64-bit MAC against a 10^15-attempt adversary
(`2^49.8`) gives `5.4 × 10^-5` - unacceptable; 96 bits gives `1.3 × 10^-14`.

A 128-bit variant at P=256 was considered and **rejected for v1**: 96 bits already
carries 12 bits of headroom at the enforced caps, while a 128-bit MAC makes the
frame 232 raw bits and the codeword 696 symbols, which halves the conservative
P=256 copy count from two per band pair to one (1,358 / 696 = 1.95). Spending a
header flag and half the repeat margin to over-satisfy a bound that already holds
is a bad trade.

**Code.** Target rate 1/3 to 1/2 with soft-decision decoding. ECC provides *all*
spreading; no `K`-chip repetition stacked on top of it. Candidates, pure Go:

- rate-1/3 constraint-length-7 **tail-biting** convolutional with soft Viterbi -
  primary candidate. On a clean rate-1/3 channel it decodes to ≈13% crossover
  against a 17.4% Shannon limit; on *this* channel, whose effective rate is 0.392
  once the screen is counted, the corresponding figures are ≈11% and 14.9%.
- repetition + soft combining - baseline for comparison.
- short LDPC - only if a clean pure-Go implementation is feasible.

Tail-biting matters for capacity: it terminates the trellis without flush bits,
so 200 raw bits code to exactly `200 × 3 = 600` symbols. If tail-biting is
dropped for implementation simplicity, six tail bits make it `206 × 3 = 618`
symbols, which no longer fits the conservative per-band-pair budget at P=192.

**Raw-BER figures are engineering guidance, not gates.** The analysis is
frame-length invariant: the attested frame's `360/918` equals the compact frame's
`200/510` equals **0.392**, so every rate and threshold below applies unchanged to
both. With ≈15% of symbols self-signaled down, a 600-symbol codeword carrying 200
information bits has an effective rate of `200/510 = 0.392`, whose BSC Shannon
crossover is **14.9%** and
whose practical constraint-length-7 soft-Viterbi threshold is **≈11%** - not the
13% quoted in r1, which was the crossover for a clean rate-1/3 channel that this
design does not have. Rate 1/2 has a Shannon limit of 11.0% and a practical
threshold of ≈8%.

The primary Phase 0 gate is therefore a **measured frame error rate**, not a BER:
FER ≤ 10% on embeddable windows at Q75 + 17° + 0.8x, run through the real encoder,
modulator, screen and decoder chain. BER is an intermediate quantity that depends
on assumptions - independence, Gaussianity, a known erasure map - that this
channel does not satisfy. Measuring the frame outcome sidesteps all of them.

**The capacity screen is global per image, not per occurrence.** There is one tile
for the whole image, so a data bin cannot be screened in one occurrence and kept in
another. For each data bin the embedder aggregates the feasible amplitude across
all occurrences, weighted by the gain field, and zeroes the bin when that aggregate
falls below a stated floor. A bin that is unusable only where the gain is already
low costs almost nothing; a bin that is unusable across the high-gain occurrences
is dropped. The screen is therefore an image-level decision on a single shared
codebook, and this is normative.

**The screen produces self-signaling soft erasures, not a known erasure map.** The
decoder does **not** receive the screened-position list and must not be designed as
if it did. Screened bins behave partly as erasures and partly as errors.

**Reliability weights come from a pilot-based noise estimate, not from observed
magnitude.** This is normative and it is easy to get wrong: a bin whose watermark
amplitude was zeroed still contains an arbitrary host coefficient, which may be
large. Raw observed magnitude is therefore **not** a valid reliability weight - it
would confidently mis-weight exactly the screened bins the decoder most needs to
discount. Instead:

1. After alignment, compute the residuals of the `S` sync pilots against the known
   complex template.
2. Estimate a per-band noise variance from those residuals.
3. Scale each data bin's matched-filter output by the estimate for its band to form
   the LLR.

The pilots are the only bins whose transmitted value the decoder knows exactly,
which is what makes them the correct noise reference. Phase 0 validates the
estimator against ground-truth noise before the code selection is finalized.

**Repeat layout is complementary band pairing, not interleaving across all four
bands.** Copy 1 occupies bands 1-2, copy 2 occupies bands 3-4, and interleaving
runs *within* each copy only. The reason is the downscale erasure budget: at 0.5x
bands 3-4 are treated as erased, and complementary pairing means copy 1 survives
**complete** - one full soft codeword - instead of both copies losing half their
symbols.

### 3b. Attested frames (public verifiability)

The compact frame authenticates with a symmetric MAC, so checking a mark requires
the same class of secret that produces one. The owner requires public-key
semantics: **verifying must not require the secret that embeds**. The attested
frame type supplies that.

```
COMPACT  (existing)  header 8 + token 96 + HMAC      96 = 200 raw bits
ATTESTED (new)       header 8 + token 96 + signature 256 = 360 raw bits
```

The 4-bit flags nibble is fully allocated: **1 bit frame mode**, **2 bits signing
key generation**, **1 bit reserved (must be 0)**. The header is inside the signed
message, so the mode bit cannot be flipped to force a downgrade - altering it
invalidates the signature.

**What the attested frame proves.** Exactly one thing: **a valid MTN-issued token
is present** - evidence-model claim 1. It does not prove what the token was issued
for, and it does not prove anything about the pixels. To a third party the token is
an **opaque 96-bit identifier**; the signature proves MTN issued *it*, not what it
was issued for. Resolving a token to an asset is an MTN-internal lookup and is not
part of standalone verification, by design and by owner decision.

#### Cryptographic scheme (normative)

Basic (non-aggregate) BLS in the **minimal-signature** orientation over BN254:

| element | group | encoding |
|---------|-------|----------|
| signature | **G1** | 32-byte compressed |
| public key | **G2** | 64-byte compressed |

Hash-to-curve is **RFC 9380 `hash_to_curve` (uniform; never `encode_to_curve`)**
to G1. RFC 9380 defines no BN254 suite, so v1 pins a custom one in full:

```
map:            SVDW
expand_message: expand_message_xmd
hash:           SHA-256
k:              128
cofactor:       clear_cofactor applied (mandatory)
DST:            "MTN-VERUM-V1-BLS-BN254G1_XMD:SHA-256_SVDW_RO_"
```

**Strict decoding is mandatory on both the signature and the public key**: correct
length, canonical field element, on-curve, correct subgroup, non-identity. The
subgroup check is not optional and is not implied - `PairingCheck` performs **no**
subgroup validation, so a caller relying on it alone accepts small-subgroup
elements. Public-key validation is mandatory at load time, not at first use.

Scope note, because the checks are not symmetric: **BN254 G1 is prime-order**, so
no wrong-subgroup G1 point exists and the subgroup check is meaningful for **G2
public keys only**. The G1 signature still needs length, canonicality, on-curve and
non-identity checks. Stating this prevents both a useless G1 subgroup check and,
worse, the inference that G2 can skip one.

**Primitive source, stated honestly.** gnark-crypto supplies BN254 field
arithmetic, the pairing, and hash-to-curve primitives. It ships **no native BLS
signature scheme**: the scheme assembly above *is this specification*, not a
library call. gnark-crypto is not fully audited and offers no constant-time
guarantee. Two things bound that exposure: signing runs only inside the KMS or an
isolated signer service, so side-channel reach is limited to that boundary, and
verification operates purely on public inputs where timing leaks nothing.
**Phase 3 is the pinning point.** The custom-suite constants and the exact
gnark-crypto version are pinned there, together with **published interoperability
vectors**; the spec is not considered implementable until they exist. Calling the
suite "exact" before that pinning would be an overclaim, since a suite is only
reproducible once its constants and its reference implementation version are both
fixed.

Rogue-key attacks and proof-of-possession are **not applicable**: there is a single
trusted signer and no aggregation. If aggregation is ever added, this decision must
be revisited before any multi-signer verification ships.

**BN254 security is ≈100 bits**, post-exTNFS. That is accepted here because a
watermark signature authenticates a provenance token, not a key exchange or a
long-lived financial commitment.

**BLS12-381 is rejected for v1.** Its 48-byte G1 point makes the frame
`8 + 96 + 384 = 488` raw bits and the rate-1/3 codeword **1,464 symbols**, which
fits no band pair at any supported `P` under either halo bound - re-breaking
exactly the capacity fit the 128-bit MAC variant was deleted for, and by a wider
margin. Revisit only if a future `P` or code rate creates the room.

#### Signed message serialization (normative)

This exact byte string is the hash-to-curve input:

```
LP("mtn-verum/attested-frame/v1") ‖ LP(header) ‖ LP(token) ‖
LP(signalGroupID) ‖ LP(epochID) ‖ u16be(P) ‖ u8(signingKeyID)

LP(x)      = u16be(len(x)) ‖ x
u16be(n)   = big-endian unsigned 16-bit
u8(n)      = unsigned 8-bit
```

`signingKeyID` is normatively **the two header bits, extracted** - never an
independent input. Passing it separately would allow a signature over a
generation ID that disagrees with the header the verifier reads, which is exactly
the substitution the binding is meant to prevent.

Binding `signalGroupID`, `epochID` and `P` **kills configuration-context replay**:
a captured frame re-encoded under a different patch size, epoch or signal group no
longer validates. Without those fields a signature captured from one deployment
context would transfer freely into another.

**Signing key generations.** The 2-bit `signingKeyID` selects one of **four
generations directly** - there is no trial verification across keys. Rotation
issues a new generation ID and **IDs are never reused**. Two bits therefore give
**four generations for the lifetime of `PayloadVersion` 1**, not four at a time:
once the fourth is retired, a further rotation **requires a `PayloadVersion`
bump**. That is normative, and it is the honest reading of a 2-bit field - treating
the ring as a recycling buffer would make an old mark verify against a new key.

**Revocation makes a mark unverified, not flagged.** When a generation is
compromised, its key stays pinned and is marked revoked, and a signature under it
yields **`Verified = false`** in the default result. The reason is that a
compromised signing key produces post-compromise signatures indistinguishable from
pre-compromise ones, so issuance authenticity for *every* mark under that
generation becomes indeterminate - not merely suspect. Reporting `Verified = true`
with a revocation note would let any caller ignore the note and act on a token
whose provenance nobody can establish. The detail - *valid signature under revoked
generation g* - appears **only** in `ForensicReport` and the verifier's verbose
output, where a human is reading it.

#### Key roles

Four roles, in two groups that differ by whether they can ever leave MTN:

| role | key | group | holding it means |
|------|-----|-------|------------------|
| signing | BLS private scalar (per generation) | **issuance secrets** | can mint new valid tokens |
| payload-token derivation | `payloadTagKey` | **issuance secrets** | derives canonical token identifiers; cannot authenticate them without the signer |
| signal / detection | `SignalKeys` epoch ring | **verification bundle** | can locate, pose-recover and decode |
| public verification | pinned BLS public keys | **verification bundle** | can authenticate a decoded frame |

**Issuance secrets are never distributed.** They live in KMS behind the `Signer`
interface. **The verification bundle is distributable**, and holding all of it
gives full standalone image verification - locate, decode, authenticate - with
**zero token-minting capability**. `payloadTagKey` is explicitly *not* part of the
bundle: it is an issuance secret and shipping it would hand out minting ability.

**The bundle is an authenticated manifest, and that resolves how something can be
both baked in and distributable.** Those two properties belong to different
objects. What is baked into the verifier binary is one **bundle-root public key**.
What is distributed is a **signed manifest** containing the signal-key epoch ring,
the verify-key generation ring, the revocation list and generation metadata. The
verifier accepts a bundle only if the manifest verifies under the baked-in root:

```
baked in (immutable)      bundle-root public key
distributed (signed)      manifest{ signal keys, verify-key ring,
                                    revocation list, generation metadata }
```

`Config.Bundle` therefore accepts only a successfully manifest-verified bundle,
constructed by `OpenBundle` and by nothing else, and the CLI **never accepts
caller-supplied raw keys**. This is what stops "public verifiability" from
degrading into "trust whoever configured the tool": an attacker who hands a victim
a doctored key set cannot get it loaded, and revocation propagates because the
revocation list is inside the signed manifest rather than in local configuration.

In attested mode the frame keys (`ActiveKey` / `DetectionKeys`) are **embed-only**,
used solely for `payloadTagKey` derivation. An attested-only deployment configures
**no detection keys at all**, and `Config.validate` scopes the requirement to the
mode. That is the selling point, and under the selected Public posture it is what
makes publishing the bundle safe: MTN hands out nothing frame-side.

#### Distribution postures

The postures describe **verification-bundle distribution**:

| posture | who can verify images | who can check an exported frame | third-party image verification? |
|---------|----------------------|--------------------------------|--------------------------------|
| **Private** | MTN only | anyone | **no** |
| **Partner** | named third parties under agreement | anyone | yes, for those parties |
| **Public** ✅ **selected** | anyone, fully offline | anyone | yes, universally |

**The owner selected Public on 2026-08-14.** The verification bundle is published
and anyone can verify any image fully offline. The table above stays as
documentation of the alternatives, because **bundle distribution is policy, not
format**: reverting to Partner or Private changes no bits on any image and no line
of the on-image specification, so MTN can revert operationally at any time by
withdrawing the published bundle. Marks already embedded are unaffected either way.

Private is documented as a fallback rather than an alternative for a specific
reason: it does **not** satisfy the owner's public-verifiability requirement. Under
Private a third party can check a signature on frame bytes MTN exports, but it
cannot verify an *image*, because it cannot locate or decode the mark. "Verify
without the embed secret" is delivered by **Partner or Public only**.

The two costs accepted with the Public selection:

1. **The removal skill floor drops** from "implements the fold attack" to "runs the
    published tool in a loop". This is an already-accepted exposure, not a new one.
2. **Replay synthesis becomes clean.** A bundle holder can decode a valid signed
    token from one image and re-embed it into another at full strength, with no
    residual estimation and therefore no SNR penalty.

Neither cost touches minting: under Public, as under every posture, creating a new
signed token still requires the signing key. None of this reopens the minimal-API
oracle design - the library's default result stays binary in every posture, and the
public verifier is a deterministic public-input algorithm with no secret an oracle
could leak.

**What a detection party can and cannot do**, stated exactly: it **cannot create a
new signed token**; it **can replay and freshly re-embed any previously observed
signed token**. That is consistent with the accepted transplant posture, and it is
precisely why a validating mark proves token issuance and never image provenance.

**FrameMode is per-tenant configuration**, because at P=192 it is a genuine trade
rather than an upgrade - see the capacity budget. Default: **attested at P=256,
compact at P=192**, with explicit override allowed. The P=256 default is attested
because public verifiability is the owner requirement that motivates the mode at
all, and the 3 dB soft-combining cost is a stated price rather than a hidden one;
**Phase 0's FER gate is the arbiter**, and if attested-mode FER fails ≤10% at P=256
where compact passes, the default flips to compact as a named Phase 0 outcome.

#### Detection with two frame lengths

The mode bit lives *inside* the frame, so a blind detector cannot know the codeword
length before decoding. It therefore **tries both**: compact (600 symbols, cheaper)
first, attested (1,080) second. `DetectionConfig.FrameModeHint` (`none` | `compact`
| `attested`) skips one decode when the caller knows its own deployment; the
default is `none`, which preserves the blind mixed-corpus guarantee. Both-decode
failure follows the same uniform-output rules as every other failure path.

**Early rejection before pairing** is normative, because a pairing is far more
expensive than the checks that can precede it. Per Viterbi survivor, in order:

1. **Header check**: version nibble == 1 (2⁻⁴), reserved flag bit == 0 (2⁻¹),
   mode bit == attested (2⁻¹), and the `signingKeyID` selecting a **populated**
   generation slot.
2. **Strict signature point decode**: the full check list above (≈2⁻¹).

The generation-slot check is free when fewer than four generations exist, but the
budget takes no credit for it - with all four populated it rejects nothing, and
that is the conservative case used here. A random candidate therefore reaches a
pairing with probability ≈2⁻⁷ ≈ **0.78%**, giving ≈**0.25** expected pairings per
negative image across 32 candidates, worst case 32.

These are *model* figures, and the caveat matters: **Viterbi survivors are not
uniform random**. A decoder driven by structured host content produces correlated
candidate bits, so the real survival rate could differ in either direction. The
published pairing rate is therefore a **Phase 6 measurement**, and the numbers here
are the budget it will be checked against.

**False validation.** The ≈100-bit figure is BN254's **attack work factor**, not an
acceptance probability - conflating the two is a common and misleading shortcut.
The acceptance probability for a random candidate is far below 2⁻¹⁰⁰. Bounding it
conservatively *at* 2⁻¹⁰⁰ and accumulating across the same lifetime trial budget
used for the MAC derivation gives `1.26 × 10¹³ / 2¹⁰⁰ ≈ 9.9 × 10⁻¹⁸ ≈ 2⁻⁵⁶·⁵`,
five orders below the 10⁻¹² target. Signature verification replaces the MAC union
bound for attested frames, and it does so with enormous margin.


### 4. Key schedule and lifecycle

HKDF with named arguments throughout, per RFC 5869 - `Extract(salt, IKM)`, never
the reversed form v2 wrote:

```
signalPRK  = HKDF-Extract(salt = "mtn-verum/v1/signal-root", IKM = SignalKey.Secret)
framePRK   = HKDF-Extract(salt = "mtn-verum/v1/frame-root",  IKM = Key.Secret)

sigCtx(label) = LP(label) ‖ LP(suiteID) ‖ LP(signalGroupID) ‖ LP(epochID) ‖
                LP(u16(P)) ‖ LP(u8(PayloadVersion))
frameCtx(lbl) = LP(lbl) ‖ LP(suiteID) ‖ LP(signalGroupID) ‖
                LP(u8(PayloadVersion)) ‖ LP(keyID)

epochPRK      = HKDF-Expand(signalPRK, sigCtx("epoch"), 32)
constKey      = HKDF-Expand(epochPRK,  sigCtx("constellation"), 32)
binPlanKey    = HKDF-Expand(epochPRK,  sigCtx("bin-plan"),      32)
dataChipKey   = HKDF-Expand(epochPRK,  sigCtx("data-chips"),    32)
payloadTagKey = HKDF-Expand(framePRK,  frameCtx("payload-tag"), 32)
frameMACKey   = HKDF-Expand(framePRK,  frameCtx("frame-mac"),   32)
```

`LP(x)` is a length-prefixed encoding; every context is unambiguously parseable.
`suiteID` is the constant `"mtn-verum/v1"`; `signalGroupID` is the new
`Config.SignalGroupID` tenant identifier.

The two context shapes differ deliberately. **The frame context carries neither
`epochID`, `P`, nor profile** - only suite, signal group, version and key ID. That
keeps frame MAC checking `O(K)`: one derived key per configured frame key, reusable
across every epoch and patch-size hypothesis the detector explores. Binding the
frame key to the epoch would have multiplied MAC-key derivations by `E` for no
security gain, since the epoch is already authenticated by which signal template
decoded the frame at all.

`signalGroupID` **is** in the frame context, and it is `O(1)` there because a given
deployment authenticates under one group. It prevents cross-group frame replay: a
frame minted for tenant A must not validate under tenant B's detector even if the
two share a frame key by accident or misconfiguration.

**The signal context drops profile** as well. Layout is profile-independent -
only amplitude differs by strength - so the detector never has to hypothesize a
profile. `P` stays in the signal context because the detector already iterates
patch sizes by search.

`payloadTagKey` is new - v2 computed the payload tag with the raw frame secret
(the behaviour of `payload.go:46` today), which is a domain-separation defect.
All HMAC-DRBG instantiations record their exact input encoding in
`internal/carrier/doc_kdf.md`.

**Signal epochs.** The carrier itself rotates. `Config.SignalKeys` is a ring of
`{EpochID, Secret}`; embed uses the newest, detect iterates the ring across the
keyed stages 0-2 (fold, global candidates, coarse discovery). Even there the ×E
cost lands only on the keyed correlation, not on the shared transform pipeline -
see the performance budget - and frame-MAC checks stay `O(K)` because the frame
context omits the epoch. The ring is capped at 8. Recommended rotation: every
~50,000 embedded images or 6 months, whichever comes first.

**Layout is fixed per `(epochID, P)`; the nonce plays no role in it.** v2's
reserve-bin perturbation was a placebo - it lived in bins the detector ignored,
consuming visibility budget while sync and data support stayed deterministic. The
v2.1-r0 replacement, nonce-keyed subset selection within a larger candidate set,
is **also removed**: it would have made the constellation payload-dependent, so
the detector would have had to search subsets it cannot know before decoding, and
the diluted per-bin observation count bought far less than it cost. Collusion and
template exposure within an epoch are bounded by **epoch rotation alone**, and the
numbers below are stated at fixed support (`f = 1`, every image contributing to
every bin) with no dilution credit taken.

**Corpus-averaging exposure, stated rather than denied.** A fixed carrier observed
across `N` images at ~28 tile occurrences per 1024² image (P=192) yields `28N`
coherent observations, i.e. `10·log₁₀(28N)` dB of estimation gain at `f = 1`:
**34.5 dB at N=100** and **61.5 dB at the recommended 50,000-image epoch cap, if
the caller enforces that cap**. The qualifier is not hedging: this package embeds
one image at a time and has no way to count issuances, so the cap is a **normative
caller requirement**, not something `Config.validate` can check. The embedding
service must maintain a per-epoch issuance counter and rotate - or refuse to embed -
at 50,000. That requirement belongs in NOTICE and is inherited by the mtnai
integration. Absent caller enforcement there is no bound at all, and the 61.5 dB
figure becomes meaningless rather than conservative. Phase 7 runs template
estimation at N = 1/4/16/64/256 and extrapolates a fitted curve to the cap.

**Key management.** Signal and frame roots live in KMS/HSM; embedding workers hold
only current-epoch subkeys; signal and frame roles are separated so one
compromised environment does not grant both removal and forgery. Key and epoch IDs
are authenticated MAC context. Access is audit logged. Retired epoch secrets are
retained for detection only, in a separate role, for a documented window; deleting
them orphans previously marked images.

**Nonce.** `Payload.Nonce` becomes mandatory at ≥16 bytes, a length
`Config.validate` enforces (today's may be empty and reused). Sourcing it from a
CSPRNG is a **caller duty**: no library check can distinguish 16 random bytes from
16 predictable ones, so the requirement is documented in NOTICE rather than
pretended to be validated. Its only role
is payload-token entropy: `token = HMAC(payloadTagKey, canonicalPayload)`
truncated to 96 bits, where the canonical payload includes the nonce. It does not
influence carrier layout, bin assignment or amplitude.

## Detector

Coarse-to-fine is the default. The v2 exhaustive sweep becomes an opt-in forensic
mode priced honestly.

```
stage 0  folded fast path      average P×P-aligned blocks, one keyed correlation
stage 1  global candidates     full-image FFT + keyed constellation matched
                               filter over (θ, s) hypotheses
stage 2  coarse discovery      stride P/2 over octave pyramid {0.5, 1, 2}
stage 3  local refinement      (position, θ, s, τ) around the top 32 candidates
stage 4  decode + authenticate soft ECC decode, then MAC or BLS signature per mode
```

Stage 0 folds the image into one `P×P` accumulator by averaging `P`-aligned
blocks and correlates against the keyed tile. Two properties are normative. It is
**keyed**, so like stages 1 and 2 it iterates the signal key ring. And its correlation
is a **maximization over all `P²` circular lags**, never a zero-lag test: an
untransformed image whose origin does not coincide with the embed origin - any
crop, any pad - still folds coherently, just at a nonzero lag. A test asserts
detection at every origin offset mod `P`. Cost ≈10 ms at E=1.

Stage 1 exploits the fact that a periodic tile produces a frequency lattice in the
*full-image* spectrum, so global pose hypotheses come from one 1024² FFT rather
than per-window search. Two caveats keep it an accelerator rather than a
correctness dependency. A 192² marked patch is 3.5% of a 1024² image, diluting
lattice SNR by 14.5 dB in the composite case. And the emitted signal is a periodic
carrier times a bilinearly smoothed - spectrally concentrated but **not**
band-limited - gain field, rather than an exactly periodic signal, so the gain
field's spectrum convolves the lattice lines and broadens them. When
`P ∤ N` the lattice also falls between bins; the budget carries a ±1-bin
interpolation cost for that. Stage 2 is the fallback that must find small pasted
regions.

Stage 2 uses stride `P/2`. Stride `P` was too coarse: worst-case displacement
`P/2` on both axes leaves only `(1 - 1/2)² = 25%` overlap with an exactly-`P`
region. Stride `P/2` gives worst-case displacement `P/4` and
`(1 - 1/4)² = 56.25%` overlap. Neither figure alone buys coverage - that is
stage 3's local `(position, θ, s)` refinement around a tolerant coarse threshold -
but 25% was too little support for the coarse statistic to fire reliably in the
first place. v2's stride `P/4` remains rejected: it double-covered the scale axis
Fourier-Mellin already recovers intra-octave, at 4× the window count.

Stage 3 refines the top `MaxWindowsToCheck` candidates, **default 32**, matching
the refinement count the performance budget is built on. Candidate recall - the
fraction of truly marked windows surviving stages 0-2 into stage 3 - carries a
**release threshold of ≥95%** on the composite corpus, measured in Phase 6. It is
a gate, not an observation.

`DetectionConfig.ForensicSweep = true` enables the exhaustive stride-`P/4`,
seven-level sweep at its honest cost of tens of seconds single-core.

**Stage 2 maximizes over the full log-polar correlation surface.** All
`128 × 64 = 8,192` cells of the log-polar phase correlation are candidates, not a
sampled subset of poses. Sampling 8 poses would have wasted the resample the stage
already pays for, and would have quietly assumed the true pose lands near a sample.

**Search-trial count `T`.** Every threshold in this design is a max-statistic
threshold, so the multiple-hypothesis count has to be derived, not guessed. For
the default pipeline at 1024², E=1:

| stage | P=192 trials | P=256 trials | derivation |
|-------|--------------|--------------|-----------|
| 0 | 36,864 | 65,536 | max over all `P²` circular fold lags |
| 1 | 4,320 | 4,320 | 360 rotation × 12 scale hypotheses |
| 2 | 8,142,848 | 4,636,672 | windows × 2 pose branches × 8,192 surface cells |
| 3 | 1,179,648 | 2,097,152 | 32 refinements × `P²` τ lags |
| **T** | **≈9.36 × 10⁶** | **≈6.80 × 10⁶** | |
| per-trial FP for 10⁻⁴ per image | **1.07 × 10⁻¹¹** | **1.47 × 10⁻¹¹** | |

**Stage 2 now dominates**, contributing 87% of the trials at P=192 - the full
surface is 1,024× more hypotheses per window than the 8-pose sampling assumed in
r1, and it swamps stage 3's `P²` τ surfaces. P=256 has a lower total despite
costlier windows, because 283 windows at stride 128 is 57% of P=192's 497.

The extrapolation gap widens accordingly: 1.3×10⁷ empirical negative trials bound
the per-window rate to 2.3×10⁻⁷, which is **≈4.3 orders of magnitude** above the
1.07×10⁻¹¹ the operating point needs. The threshold therefore comes from a
parametric tail model of the correlation statistic under H₀, with the empirical
trials validating that model's tail only as far as 2.3×10⁻⁷. This gap is stated,
not closed, and it is wider in r2 than it was in r1 precisely because the honest
trial count is larger.

**Estimated inlier fraction** replaces v2's `Coverage`. Alpha coverage is
unobservable once a pasted region has been flattened onto an opaque background,
so support is estimated from the sync residual: the fraction of constellation
peaks whose likelihood exceeds the per-peak threshold under the refined pose.

## Perceptual masking and quality

Perceptual shaping is a **smoothly varying gain envelope**, not an iterative
projection. v2's spatial multiply of a band-limited carrier by an arbitrary local
mask convolves in frequency with an unbounded kernel, destroying the
sync/data/halo separation the design depends on. An iterative projection loop
would repair that but needs a convergence argument nobody has, and it still has to
choose what to sacrifice each iteration. The gain envelope achieves the same end
in closed form:

1. Synthesize the `P×P` tile once from the constellation and coded data symbols.
2. For each tile occurrence `n`, compute the per-pixel cap ratio
   `Watson cap / |tile residual|` and take `g_n = ` its **5th percentile**, not its
   minimum. The trade is named: `min` guarantees the cap at every pixel but lets a
   handful of pixels collapse the amplitude of a whole `P×P` occurrence. Those
   pixels are **smooth mid-luminance ones** - Watson thresholds rise where masking
   is strong, so textured regions, hard edges and specular highlights have *high*
   caps, and the binding minimum comes from the flattest, mid-grey part of the
   occurrence. `p5` accepts cap violation on up to 5% of pixels in exchange for a
   usable amplitude.
3. Sample `g` once per occurrence at the occurrence center and **bilinearly
   interpolate** between centers. This interpolation *is* the smoothing mechanism -
   there is no separate low-pass step. Bilinear interpolation of a grid spaced `P`
   apart convolves with a triangular kernel of width `2P`, spectrum `sinc²(fP)`:
   **main-lobe first null** at `f = 1/P`, first sidelobe **−26.5 dB**. The null is
   where energy is concentrated to, not a limit it is confined by.
4. Emit `residual(x) = interpolated_gain(x) · tile(x mod P)`.

**The gain field is not band-limited, and the doc does not claim it is.** `sinc²`
sidelobes decay but extend indefinitely, so some gain-field energy always lands
outside `1/P` and therefore some carrier energy always lands outside its guard
halo. How much is a **measured quantity**, not a bounded one: Phase 0 measures the
out-of-halo leakage fraction, and that measurement feeds directly into which halo
bound binds in the capacity budget. Earlier drafts asserted a `1/(2P)` bandwidth
limit; that assertion was wrong and is withdrawn.

Cap violation is likewise **measured, not claimed bounded**. There is no clamp: an
earlier draft capped `g_n` at `1.25 ×` the occurrence minimum, but that binds
against exactly the single-extreme-pixel minimum `p5` was chosen to escape - inert
whenever the occurrence is well behaved, and actively harmful in the case that
motivated `p5`. The police are the ones already named in step 2: the Phase 0
cap-violation budget and, in production, the p1 local SSIM gate. There is no loop,
no convergence question, and no full-image FFT in the embed path.

The honest consequence, stated because it propagates: **the emitted signal is a
periodic carrier times a bilinearly smoothed gain field - spectrally concentrated
but not band-limited - rather than an exactly periodic signal.** The gain field's
spectrum convolves the lattice lines, which is exactly why stage 1 is an
accelerator rather than a correctness dependency. Stage 0
folding tolerates it because folding sums the gain coherently - a positive gain
field cannot cancel - and because the fold correlation maximizes over all lags.
The convolution is concentrated inside the `1/P` **main-lobe first null** of the
interpolation kernel - a concentration point, never a bandwidth bound - and its
measured out-of-halo tail is a Phase 0 deliverable rather than an assumption.

The gain field **is** the embeddability map. Occurrences whose gain falls below a
stated floor are not embeddable and are excluded from the support contract. This
is what prevents the failure mode where one large smooth region - a sky - drags a
single global amplitude down and silently weakens the mark everywhere else: the
sky gets a low local gain and is reported as unprotected, while textured regions
keep full amplitude.

**Granularity, stated honestly.** The map resolves at `P` - one sample per
occurrence, bilinearly interpolated - **not** at object boundaries. A textured
subject occupying a third of a smooth occurrence does not get its own protected
region; it is averaged into that occurrence's percentile. `ProtectedAreaRatio` is
consequently a `P`-granular estimate and should never be presented as a pixel-exact
protected mask. Phase 0 additionally measures the **realized**
`ProtectedAreaRatio` across the five fixture classes, so the spike catches the
case where the shipped embedder cannot reach the amplitude the spike assumed.

v1's attenuate-and-retry loop around the quality gates is kept. Self-detection is
a **minimum-robust-amplitude binary search** between the quality ceiling and the
detection floor rather than a single-shot embed-then-check. For
`StrengthBalanced` and `StrengthRobust`, self-verification includes a real Q75
round trip and **five crop phases** - the four half-period corner offsets plus one
keyed random offset - not just a native-scale decode.

**Quality metrics.** The public SSIM ≥ 0.995 claim is made against canonical
11×11 Gaussian-windowed SSIM (σ = 1.5) on BT.601 luma, with border handling and
aggregation frozen and documented. v1's `internal/quality` uses an 8×8 box
approximation and is upgraded. Global metrics hide local periodic artifacts, so
the gate set adds:

- local-percentile SSIM: p1 over 11×11 windows ≥ 0.985
- local RMS cap per 32×32 block
- spectral-line visibility limit: the embed peak-amplitude parameter is `a_e` and
  the gate multiplier is `a_gate = 1.5 · a_e`, so the quality gate trips only on a
  1.5× margin above the amplitude the embedder targets - the two are separate
  named parameters, never the same constant reused
- smooth-region artifact check on blocks below a texture-variance floor

## Support contract and claims

Detection is claimed only for regions containing at least one locally
**embeddable** `P`-window - not any `P`-window of original source pixels.

The distinction is quantitative. For a near-constant patch,
`SSIM ≈ C2 / (C2 + σ_w²)` with `C2 = (0.03 · 255)² = 58.52`. At SSIM = 0.995 this
gives `σ_w² = 58.52/0.995 - 58.52 = 0.294`, so the watermark RMS is capped at
**0.54 luma levels**. JPEG Q75 luminance quantization steps in the 0.08-0.22
cycles/pixel band - 8×8 DCT radial indices 1.3 to 3.5 - are 5 to 10 units. A
smooth patch therefore cannot carry a Q75-survivable mark at the stated
visibility budget. Claiming recovery from every `P`-patch is not credible and
v2.1 does not claim it.

Embed produces a per-window **embeddability map**, which is the interpolated gain
field thresholded at the embeddability floor - the same object the masking section
builds, not a second independent screen. `QualityReport` gains:

```go
type QualityReport struct {
    SSIM              float64
    LocalSSIMP1       float64
    PSNR              float64
    MaxDelta          float64
    ProtectedAreaRatio float64          // fraction of the image inside embeddable windows
    ProtectedRegions  []image.Rectangle // coarse summary, merged
}
```

`ProtectedAreaRatio` is what the caller communicates to the user. A generated
image that is 40% sky gets a 60% figure, and cropping the sky yields nothing.
That is an information-capacity limit, stated up front rather than discovered in
production.

## Capacity budget

Annulus pair count for `[0.08, 0.22]` cycles/pixel:
`(π/2)(0.22² - 0.08²)·P² = 0.06597·P²`, enumerated exactly on the integer bin
lattice. Per-band enumerated conjugate-pair counts:

| P | band 1 | band 2 | band 3 | band 4 | total | pair 1-2 | pair 3-4 |
|---|--------|--------|--------|--------|-------|----------|----------|
| 192 | 596 | 616 | 612 | 612 | 2,436 | 1,212 | 1,224 |
| 256 | 1,088 | 1,070 | 1,090 | 1,078 | 4,326 | 2,158 | 2,168 |

Equal *area* does not give equal enumerated counts, and the imbalance is not
negligible at P=256 (1,070 versus 1,090). The budget uses these enumerated
numbers, never an equal-count idealization.

Two halo geometries bracket the guard cost and **both are carried through**,
because which one binds is a Phase 0/1 measurement, not a design choice:

| bound | geometry | pairs per peak |
|-------|----------|----------------|
| optimistic | circular disk `r = 2` | `π·4 = 12.57` → 13 |
| conservative | square `±2` guard, matching the separable Hann mainlobe | `5×5` = 25 |

`S` is sized so the **conservative** bound fits: **S = 48 at P=192**, **S = 64 at
P=256**, distributed evenly across the four bands.

**Two questions, kept separate.** *Packing* asks whether the coded symbols
physically fit in the available bins - it is pure enumeration and it is settled
here. *Decode viability* asks whether they survive the channel - it is a measured
frame-error-rate question and it is settled only in Phase 0. The 0.85 screen
appears in **neither** fit calculation: it zeroes amplitudes at fixed positions
without freeing the bins, so it cannot buy or cost packing room, and its decode
effect is already inside the measured FER. Every row below therefore carries a
packing verdict and a FER verdict, and the FER column is empty until Phase 0 runs.

Two frame types must be budgeted. Tail-biting rate 1/3 gives **600 symbols** for
the 200-bit compact frame and **1,080** for the 360-bit attested frame; rate 1/2
gives 400 and 720. Under complementary band pairing a copy must fit **within one
band pair**, so the binding comparison is per band pair, not against the total.

| P | halo bound | halo cost | free 1-2 | free 3-4 | copies | packing | FER |
|---|-----------|-----------|----------|----------|--------|---------|-----|
| 192 | conservative (25) | 1,200 | 612 | 624 | 2 | fits, 12 and 24 pairs spare | Phase 0 |
| 192 | optimistic (13) | 624 | 900 | 912 | 2 | fits, 300 and 312 spare | Phase 0 |
| 256 | conservative (25) | 1,600 | 1,358 | 1,368 | 4 | fits, 158 and 168 spare | Phase 0 |
| 256 | optimistic (13) | 832 | 1,742 | 1,752 | 4 | fits, 542 and 552 spare | Phase 0 |

**Attested frames** (1,080 symbols at rate 1/3) change the picture materially:

| P | halo bound | free 1-2 | free 3-4 | fits per pair? | layout | copies | spare |
|---|-----------|----------|----------|----------------|--------|--------|-------|
| 192 | conservative | 612 | 624 | no (1,080 > 624) | one cross-four-band copy | 1 | 156 |
| 192 | optimistic | 900 | 912 | no (1,080 > 912) | one cross-four-band copy | 1 | 732 |
| 256 | conservative | 1,358 | 1,368 | **yes** | complementary pairing | 2 | 278 / 288 |
| 256 | optimistic | 1,742 | 1,752 | **yes** | complementary pairing | 2 | 662 / 672 |

- **At P=192 attested does not fit a band pair at either halo bound.** It packs
  only as a single copy spread across all four bands, so it has **no complementary
  repeat, no +3 dB soft combining, and no 0.5x claim** - 0.5x erases the bands-3-4
  portion of the only copy. Compact keeps two copies and its 0.5x claim. **This is
  the named trade at P=192: public verifiability or downscale survival, not both.**
  `FrameMode` makes it a per-tenant choice.
- **At P=256 attested fits per band pair**, giving two complementary copies, 0.5x
  survival and +3.0 dB. **It is the P=256 default.** The cost against compact is
  soft-combining gain, not fit: compact packs two copies *per pair* (four total,
  **+6.0 dB**) where attested packs one (two total, **+3.0 dB**), and at 0.5x
  compact retains +3.0 dB where attested retains 0 dB. Attested at P=256 buys
  public verifiability for 3 dB. Whether that price is affordable is a **Phase 0
  FER measurement, not a design assertion** - see the default-flip condition in the
  Phase 0 outcomes.

**Conclusion per patch size (compact frame):**

- **P=192 packs the two-copy layout under both halo bounds, but the conservative
  case leaves 12 spare pairs in band pair 1-2.** Twelve pairs out of 612 is a 2%
  margin against enumeration drift, placement rounding, or any halo that turns out
  even slightly larger than the square ±2 bound. That fragility is real and its
  mitigation is the radial placement constraint below, which guarantees no guard
  spills outside its band pair and therefore that the enumerated free counts are
  achievable rather than optimistic. If Phase 1 measures a leakage width above ±2
  bins, P=192 loses copy 2 and drops to one codeword at 0 dB.
- **P=256 packs four copies** - two per band pair - under both bounds, with 158
  spare pairs in the tightest case. At 0.5x it retains two copies in bands 1-2.
- **P=128 is removed from the supported set** (see the P=128 subsection).

The interleaver is a permutation of a copy's symbols within its own band pair, so
it consumes no additional pairs and does not compete with copy 2 for space; what
the 12-pair margin bounds is placement and enumeration slack, not interleaver depth.

**Radial placement constraint, all bands.** Every peak center sits far enough
inside its band pair that its ±2-bin guard stays within that band pair. In bins:

| P | band pair 1-2 span | allowed centers | band pair 3-4 span | allowed centers |
|---|--------------------|-----------------|--------------------|-----------------|
| 192 | 15.36 - 31.78 | 17.36 - 29.78 | 31.78 - 42.24 | 33.78 - 40.24 |
| 256 | 20.48 - 42.38 | 22.48 - 40.38 | 42.38 - 56.32 | 44.38 - 54.32 |

This serves two purposes: guards cannot consume pairs belonging to the opposite
band pair (which would silently break the complementary-copy budget), and band 4
peaks stay off the outermost bins, the first casualties of downscale and JPEG.

**Downscale erasure budget.** At 0.5x the four bands map to [0.160, 0.260],
[0.260, 0.331], [0.331, 0.389] and [0.389, 0.440] cycles/pixel in the output.
Bands 3-4 are strongly attenuated by common resampling kernels, and **the design
budget conservatively treats them as erased at 0.5x** rather than asserting they
fall above every kernel's passband. Complementary pairing is what makes this
survivable: copy 1 lives entirely in bands 1-2 and comes through complete, so
P=192 retains exactly one full rate-1/3 codeword at 0 dB margin and P=256 retains
two at +3.0 dB.

**Sync loss at 0.5x is the tighter half of that story and is not yet quantified.**
Losing bands 3-4 also removes half the constellation - `S` drops from 48 to 24 at
P=192 - which costs 3 dB of coherent pilot gain and, worse, shortens the radial
lever arm that sets scale-estimate precision. The pilot SNR requirement of
−4.2 dB was derived at S=48. Phase 0 measures pose and τ recovery at 0.5x
directly, alongside the data-erasure budget, and the 0.5x capability claim is
gated on that measurement rather than inferred from the data layer alone.

**Fallback arm (a') accounting.** Noncoherent differential-energy modulation pairs
bins, halving symbol capacity. Packing only - all figures are physical:

| P | halo | symbols 1-2 | symbols 3-4 | total | compact (600 / 400) | attested (1,080 / 720) |
|---|------|-------------|-------------|-------|---------------------|------------------------|
| 192 | conservative | 306 | 312 | 618 | 600 fits **marginally**, cross-band only | **no fit at any rate** (1,080 and 720 both > 618) |
| 192 | optimistic | 450 | 456 | 906 | 600 fits cross-band | rate 1/2 (720) fits cross-band, 186 spare; rate 1/3 does not |
| 256 | conservative | 679 | 684 | 1,363 | two complementary copies | rate 1/3 (1,080) fits cross-band, 283 spare; no pairing |
| 256 | optimistic | 871 | 876 | 1,747 | two complementary copies | rate 1/3 fits cross-band, 667 spare; rate 1/2 fits **per pair** |

The compact P=192 verdict needs its reason stated: 306 and 312 differential symbols
per band pair are both far below 600, so no single copy fits inside a band pair. The
codeword must spread across all four bands, consuming 600 of 618 available symbols
with 18 to spare. That is why the compact fallback at P=192 carries **no 0.5x claim
at all** - erasing bands 3-4 destroys roughly half of the only copy. Compact at
P=256 keeps complementary pairing and its 0.5x claim.

**Attested plus fallback is the one combination that does not work at P=192.** At
the conservative halo, 618 total differential symbols cannot hold 1,080 or even
720, so if Phase 0 selects the noncoherent arm, **attested mode is P=256-only**.
Under the optimistic halo P=192 recovers a rate-1/2 attested option (720 within
906, cross-band, no 0.5x), so which halo bound binds decides whether that
configuration exists at all. At P=256 the attested fallback fits rate 1/3
cross-band with 283 spare - better than dropping to rate 1/2 - but never per pair,
so it carries no 0.5x claim either. If Phase 0 selects the fallback
arm, the support contract and capability claims shrink accordingly, and this is
stated now rather than discovered afterwards.

## P=128 (removed)

P=128 was in the user-confirmed parameter set. Its removal from the supported set
is **approved by the owner, 2026-08-14**. The three findings that drove it out are
kept here as the record of what was approved:

1. **Guard overhead dominates.** At P=128 the annulus holds 1,072 pairs across an
   18-bin-wide radial band. Even the optimistic 13-pairs-per-peak halo at the
   minimum S=48 consumes 624 pairs - 58% of the annulus - and the conservative
   25-pair bound consumes 1,200, which exceeds the annulus outright.
2. **The reduced frame violated the evidence model.** The only frame that fit was
   a 32-bit cohort presence token plus a 96-bit MAC. A 32-bit token collides with
   25.3% probability across a single 50,000-image epoch, so it is a *generic
   credential* identifying a cohort rather than an asset - it cannot support claim
   (ii), token provenance, at all. There is also no upgrade path: resolving the
   asset from a larger surviving window would need a hierarchical superframe that
   is not designed here.
3. **Rate-1/2-only fragility.** P=128 could not carry a rate-1/3 codeword, so it
   needed raw BER ≤ 8% on the smallest window with the least processing gain -
   a stricter channel requirement than P=192 faces, on worse evidence.

Reopening P=128 would require a hierarchical frame design - a cohort-level frame in
small windows that composes into asset-level resolution across multiple windows -
and its own Phase 0 gate. That is a separate work item, not a parameter change, and
it is not in scope for v1.

    // unexported: signal-key epoch ring, generation ring, revocation list,
    // metadata. Populated only by OpenBundle.
}

The key caps are load-bearing: the MAC union bound above is computed at `K = 16`
total tried frame keys and `E = 8`, so `Config.validate` must enforce them rather
than trusting callers.
The frame-key cap is on the **total set actually tried** -
`|{ActiveKey} ∪ DetectionKeys| ≤ 16` - not on `DetectionKeys` alone, since
`detectionKeys()` prepends the active key and it is the tried set the union bound
counts. `suiteID` is the package constant `"mtn-verum/v1"` and is not
configurable.

**The default result is binary.** v2's struct - per-region confidences, bounds,
pose estimates, partial counts, failure stage - is an efficient removal oracle: it
tells an attacker where the signal is, how strong it is, and which modification
helped. The v2.1-r0 three-valued `Band` was still an oracle, because `partial`
versus `none` is precisely the gradient an attacker climbs. It is deleted.

```go
type DetectResult struct {
    Verified       bool
    MatchedKeyID   string          // populated only when Verified
    MatchedEpochID string          // populated only when Verified
    PayloadToken   string          // hex; populated only when Verified
    FrameMode      FrameMode       // populated only when Verified
    SigningKeyID   uint8           // attested only; populated only when Verified
    Forensic       *ForensicReport // nil unless DetectionConfig.Forensic
}

type ForensicReport struct {
    Regions               []DetectionRegion
    PartialRegions        []DetectionRegion
    BestPartialLikelihood float64
    WindowsExamined       int
    Stage                 string // failure stage; forensic mode only
}

type DetectionRegion struct {
    Bounds                  image.Rectangle
    Likelihood              float64
    RotationDegrees         float64
    Scale                   float64
    EstimatedInlierFraction float64
    Verified                bool
}

type FrameModeHint string

const (
    HintNone     FrameModeHint = ""         // blind: try compact then attested
    HintCompact  FrameModeHint = "compact"  // skip the attested decode
    HintAttested FrameModeHint = "attested" // skip the compact decode
)

type DetectionConfig struct {
    FrameModeHint      FrameModeHint // "" = blind try-both; a hint only skips work
    Forensic           bool    // unlocks ForensicReport; privileged/local only
    ForensicSweep      bool    // exhaustive stride-P/4 multi-level sweep
    MaxWindowsToCheck  int     // 0 = 32
    MaxRotationDegrees float64 // 0 = full 360
    ScaleMin           float64 // 0 = calibrated lower bound
    ScaleMax           float64 // 0 = calibrated upper bound
    MaxScaledDimension int
    MaxScaledPixels    int
}
```

Every failure - no sync, partial sync, ECC failure, wrong key, MAC failure -
returns the **byte-identical zero-value `DetectResult`**. There is no field an
attacker can read to distinguish them.

**Timing uniformity is scoped honestly.** The library guarantees uniform *output*
and no failure-cause-dependent early exit *within* a stage. It does **not**
guarantee constant total runtime across causes, because an image that generates no
stage-3 candidates genuinely has no stage-3 or stage-4 work to do, and fabricating
that work would mean burning hundreds of milliseconds per negative detection.
Constant-time padding across the no-sync versus decode-failure boundary is
therefore delegated to the network wrapper, where it belongs and where a fixed
response deadline is cheap. This is normative guidance for that wrapper, not an
in-library claim.

`EstimatedInlierFraction` replaces v2's `Coverage`; its denominator is the full
fixed constellation, which is well defined precisely because layout no longer
depends on the nonce.

**Partial evidence exists only inside `ForensicReport`.** It requires either two
spatially independent pilot matches or a keyed likelihood ratio above a threshold
calibrated on the max-over-all-trials statistic, and it never sets `Verified`.

**Network detector requirements**, normative for any service wrapping this
package: expose only `Verified` and, to authorized callers, the matched key,
epoch and token; never expose `Forensic`; pad responses to a fixed deadline; rate
limit per account, per tenant and per source IP; detect near-duplicate submissions
so an attacker cannot walk a perceptually-similar image family through the oracle.

`Embed`, `Detect`, `Verify` and `IsEmbeddable` keep their signatures.
`PayloadVersion` is fixed at `1`. `Verify` gains one step for attested frames: it
checks **signature validity before** comparing the expected payload, so a bad
signature is rejected as unauthenticated rather than reported as a payload mismatch.

`FrameMode` is exposed on a verified result because a caller in the Partner or
public posture needs to know whether what it verified was publicly checkable or
merely MAC-checked. It is populated only when `Verified`, like the other
identifiers, so it leaks nothing on failure.

**`cmd/verum-verify` - standalone verifier.** A separate binary with the
**bundle-root public key** baked in, taking a signed verification-bundle manifest
per distribution posture. It has no flag for supplying raw keys. Its output is
deliberately narrow - **"valid MTN-signed token `T`", plus
the signing generation and its revocation status, and nothing else**. It does not
resolve the token to an asset, because it cannot: that is an MTN-internal lookup and
is not part of standalone verification. It follows the library's output discipline
otherwise: uniform failures, nothing an attacker can climb. It has **no network
calls and no mtnai dependency** - that is the point of it, and
`TestStandaloneVerifier` enforces it.

## Performance targets and measured basis

Measured on gonum 0.17, Intel i7-11700KF, single core:

| Operation | Measured |
|-----------|----------|
| 2D complex FFT 128² | 0.87 ms |
| 2D complex FFT 192² | 2.02 ms |
| 2D complex FFT 256² | 3.68 ms |
| 2D complex FFT 1024² | 71.9 ms |
| log-polar resample 192² | 0.79 ms |
| phase correlation 192² | 2.03 ms |
| taper + magnitude 192² | 0.11 ms |
| canonical-pose warp 192² | 0.19 ms |
| per-window full FM sync | 7.1 ms |
| per-candidate decode, terminated Viterbi | 3.5 ms |

**Window counts at 1024², P=192, stride `P/2` = 96**, octave pyramid {0.5, 1, 2}:
`⌊(512-192)/96⌋+1 = 4` → 16 windows at 0.5x, `⌊(1024-192)/96⌋+1 = 9` → 81 at 1.0x,
`⌊(2048-192)/96⌋+1 = 20` → 400 at 2.0x. **497 windows total.** v2's stride-48
seven-level 0.5-2.0 pyramid gives ≈3,600.

**The stage-2 statistic** is one pipeline: real-input FFT (192²) → taper and
magnitude → 128-wide log-polar resample → FFT-based phase correlation against the
cached epoch template, maximized over the full 128×64 surface.

| component | cost | basis | scales with E |
|-----------|------|-------|---------------|
| real-input FFT 192² | 1.01 ms | **assumed** 2× saving over the measured 2.02 ms complex FFT | no |
| taper + magnitude | 0.11 ms | measured | no |
| 128-wide log-polar | 0.40 ms | **assumed** scaling from the measured 0.79 ms at full width | no |
| forward FFT of the log-polar map | 0.17 ms | **assumed**, `N log N` scaling from the measured 2.03 ms 192² phase correlation | no |
| conjugate multiply + inverse FFT + argmax | 0.22 ms | same basis | **yes** |
| **shared / per-epoch** | **1.69 / 0.22 ms** | | |

The split matters: the window's own transforms, including the *forward* FFT of its
log-polar map, do not depend on which epoch template it is compared against. Only
the multiply, the inverse transform and the argmax repeat per epoch. The same
holds at stage 1, where the 1024² FFT is shared and only the matched filter
repeats. Stages 3 and 4 do not scale with `E` at all, because the top-32 candidate
list is already epoch-tagged.

Two r2 changes raised this budget and both are real: full-surface maximization
replaced 8-pose sampling (shared 1.52 → 1.69 ms, per-epoch 0.09 → 0.22 ms), and
tail-biting costs roughly **2× in the Viterbi core** because of the wrap-around
passes. That is the core only, not the whole candidate: of the measured 3.5 ms
per-candidate cost, ≈1.5 ms is the Viterbi core and ≈2.0 ms is demodulation,
deinterleaving and MAC. Doubling the core gives `3.0 + 2.0 = ` **5.0 ms** per
candidate (assumed pending Phase 1 measurement), so stage 4 is 32 × 5.0 = 160 ms.

| Stage | E=1 | E=2 | E=4 | E=8 |
|-------|-----|-----|-----|-----|
| 0 folded fast path (all-lags max) | 10 | 12 | 16 | 24 |
| 1 global candidates (1024² FFT + filter + ±1-bin interp) | 92 | 112 | 152 | 232 |
| 2 coarse discovery, 497 × (1.69 + 0.22E) | 949 | 1,059 | 1,277 | 1,715 |
| 3 refinement, top-32 × 9.1 ms | 291 | 291 | 291 | 291 |
| 4 decode + authenticate, 32 × 5.0 ms (compact-only detector) | 160 | 160 | 160 | 160 |
| **total single core** | **1.50 s** | **1.63 s** | **1.90 s** | **2.42 s** |

**Attested frames change stage 4 and nothing else, but the change is larger than a
single decode.** Because the mode bit is inside the frame, a blind detector tries
**both** codeword lengths per candidate.

Attested decode cost, with the 2.0 ms remainder split by what actually scales: of
it, ≈1.2 ms is demodulation and deinterleaving, which scale with symbol count, and
≈0.8 ms is the authenticate-and-pack step, which does not (both figures **assumed**,
pending Phase 1). So `3.0 × 1.8 + 1.2 × 1.8 + 0.8 =` **8.4 ms** per attested
candidate, against 5.0 for compact.

Try-both stage 4 is therefore `32 × (5.0 + 8.4) = 429 ms` of decoding, plus
pairings. Early rejection keeps pairings rare: **≈0.25 expected per negative image**
(≈0.75 ms, a modelled figure to be measured in Phase 6) and **32 worst case**
(≈96 ms at ≈3 ms each, that per-pairing figure
**assumed** pending a Phase 1 gnark-crypto benchmark, using a two-term multi-pairing
check). Stage 4 lands at **≈430 ms typical** (429 decode + 0.75 pairing) and
**≈525 ms worst case** (429 + 96), against
160 ms for a compact-only detector.

`DetectionConfig.FrameModeHint` removes one of the two decodes when the caller knows
its deployment, roughly halving the decode term.

Consequently **P=256 in its default attested mode costs ≈1.86 s typical and
≈1.96 s worst case at E=1**, against 1.59 s for a compact-only detector. Stages 0-3
are unchanged; this is entirely stage 4. Embed adds one BLS signing operation,
≈1 ms once per image - negligible against the 450 ms budget, listed for
completeness.

**The ≤1.5 s single-core target now holds at E=1 only**, and there with no margin
(1.50 s, +0.2%). r1 claimed E ≤ 4; that claim is withdrawn. At E=2 the budget is
1.63 s (+9%) and at E=4 it is 1.90 s (+26%). Detect is an async bounded job, so
the practical answer for a larger ring is concurrency - 8 cores put every column
above under 320 ms - but the single-core number should not be quoted as ≤1.5 s for
any ring larger than one. Whether to hold the target at E=1, raise the target, or
cheapen stage 2 is a decision Phase 1's measured stage-2 cost should inform.

**P=256.** Windows at stride `P/2 = 128`: `⌊(512-256)/128⌋+1 = 3` → 9,
`⌊(1024-256)/128⌋+1 = 7` → 49, `⌊(2048-256)/128⌋+1 = 15` → 225, **283 total**.
Only the components that actually depend on window size scale by the measured
3.68 / 2.02 = **1.8×** FFT ratio - the real-input FFT (1.01 → 1.84 ms) and the
taper/magnitude pass. The two scale differently and the doc uses each one's own
ratio: the FFT tracks the measured 3.68 / 2.02 = 1.82 cost ratio (1.01 → 1.84 ms),
while taper-plus-magnitude is a purely elementwise pass and therefore scales with
**pixel count**, 256²/192² = 1.778 (0.11 → **0.20 ms**). The 128-wide log-polar
resample and the forward FFT of that map produce the same-sized output at any `P`
and do not scale at all, so the **shared per-window cost rises 1.54×**, from 1.69
to **2.61 ms**, with the per-epoch term unchanged at 0.22 ms. Per-candidate FM plus
τ is ≈12.9 + 3.6 = 16.5 ms. At E=1 that gives stage 2 ≈**801 ms**, stage 3 ≈528 ms,
and a **total of ≈1.59 s** - within 6% of P=192 despite the larger windows,
because 283 windows is **57%** of 497. P=256 is not the expensive configuration it
looks like.

Published targets:

- **Default detect at E=1, single core @1024²**: ≈1.50 s at P=192 compact-only,
  ≈1.59 s at P=256 compact-only, and **≈1.86 s typical / ≈1.96 s worst case at
  P=256 attested** with blind try-both decoding (the P=256 default).
  `FrameModeHint` recovers roughly half the try-both decode term. Roughly
  200-380 ms across 8 cores. Larger rings scale as the table above.
- **Embed ≤ 450 ms p95 @1024²**, single pass. Budget: tile synthesis 2 ms, Watson
  thresholds and the gain field with its interpolation 8 ms, spatial
  compositing 15 ms, 4-probe amplitude binary search 204 ms, quality gates 65 ms,
  Q75 round-trip self-verify 61 ms, five-crop-phase self-verify 55 ms, plus ≈1 ms
  BLS signing in attested mode - **≈410 ms**.
  The binary search is capped at 4 probes; a second full retry exceeds the target.
- **Forensic sweep ≈26 s single-core**, ≈4 s across 8 cores.
- **Memory ≤ 100 MB per call** (≈50 MB working set, 70-90 MB RSS at scale 2.0)
  with the one-resample-buffer-in-flight rule. Concurrent detects must be bounded
  by the caller.

v2 claimed 200-800 ms for detect with a structure that measures ≈26 s. That claim
is withdrawn.

**Deployment.** In-process Go library. Embed runs inline - it is invisible against
multi-second generation latency. Detect is never synchronous in a request handler:
it runs as a bounded async job with concurrency 1-2. Split detect into a separate
service only if detect becomes user-facing and regular, queue p95 exceeds minutes,
measured SSE jitter appears, or memory × concurrency approaches pod limits.

## Security claims

Four separate properties. v2 conflated them.

1. **Detection resistance (weak; raises cost, does not prevent removal).**
   Without a current signal-epoch secret an attacker cannot read the payload or
   forge a frame. They **can** locate and null the constellation from a *single
   image*, with no key and no corpus:

   > Fold one 1024² image mod `P` - 28.4 tile occurrences, **14.5 dB** of coherent
   > gain. The constellation is sparse, elevated and phase-coherent in a band whose
   > limits are public, so the surviving bins stand out as outliers against the
   > local radial statistics. No key is needed to find them, only to interpret
   > them. Nulling ≈`2S` bins (96 at P=192) in a mid-frequency band is
   > perceptually cheap.

   This is the explicit v2 → v2.1 trade: v2's dense carrier was mathematically
   invalid as a detector input but *diffuse* and hard to localize; v2.1's sparse
   constellation is valid and coherently detectable but *locatable once folded*.
   Sparsity is what made the design work and what made this attack cheap.

   **This exposure is accepted, not mitigated.** Cheap single-image template
   location is fundamental to any construction with a public tile period and a
   public carrier band: folding is available to anyone who knows `P`, and `P` must
   be public because the detector has to try it blind. The one architectural escape
   - per-tile keyed layouts that break the periodicity - would destroy blind *local*
   detection, because the detector could no longer correlate an arbitrary cropped
   window against a single known template without first knowing which tile it came
   from. Nothing inside this architecture prevents fold-and-null.

   **What the design still delivers**, stated so the residual value is not
   overlooked:
   1. **Forgery resistance is untouched.** Nulling removes a mark; it does not let
      anyone produce a valid token. That still needs the 96-bit MAC key.
   2. **Detection of unmodified and casually-transformed images**, which is the
      actual product case. Users reposting, cropping, rescaling or recompressing an
      AI image do not run FFT fold attacks. The mark survives what ordinary
      redistribution does to an image.
   3. **The epoch ring bounds cross-image template reuse** and caps the blast
      radius of a key compromise to one epoch's images.

   Phase 7 delivers a measured fold+null removal-success-versus-SSIM-damage curve
   at **N = 1**. The release gate is **not** "the attack must fail" - that would be
   dishonest about a fundamental exposure. The gate is that **README, NOTICE and
   all product claims match the measured curve**, confirmed by owner sign-off
   before v1 release. The *concept* is already accepted on the record (2026-08-14),
   so what the Phase 7 sign-off confirms is the **measured curve**, not whether the
   exposure is acceptable.

   Generic periodicity detection is likewise unprevented: `P` is one of two public
   values.
2. **New-frame forgery resistance (supplied, and strengthened in attested mode).**
   For compact frames, producing a new authenticated frame requires the frame key;
   the best attack is MAC guessing at the 96-bit level derived above. For **attested
   frames it requires the BLS signing key, which no detection party holds** -
   including MTN's own detection infrastructure, and including every party in the
   Public distribution posture now selected - which is to say, everyone. Forgery
   security is ≈100 bits (BN254).
   This is the one property the attested upgrade genuinely strengthens: detection
   capability and minting capability become independent. Stated exactly, because
   "forgery is impossible for detection parties" overstates it: a detection or
   bundle-holding party **cannot create a new signed token**, but it **can replay
   and freshly re-embed any previously observed signed token**.
3. **Replay / transplant resistance (NOT supplied, and not mitigable here).** A
   valid residual extracted from image A and applied to unrelated image B validates
   as A's token on B - under both frame types; a signature is as transplantable as a
   MAC. See the evidence model. This is a documented property and is tested
   explicitly. There is **no mitigation path inside this system**: the obvious one,
   comparing the resolved token against issuance-record content, is rejected by
   owner decision because verification must be standalone.
4. **Collusion / template resistance (BOUNDED, NOT supplied).** Corpus averaging
   recovers a reusable template at the fixed-support rate stated in the key
   schedule section: 34.5 dB at N=100 and **61.5 dB at the 50,000-image epoch
   cap**. Epoch rotation is the entire bound - no codebook dilution is claimed.
   The honest statement is a measured removal-versus-damage curve, not immunity.
   Given finding 1, corpus attacks are the *expensive* path to a template; folding
   a single image is the cheap one.

**What attested frames do *not* fix.** Removal resistance is **unchanged**.
Fold-and-null strips an attested mark exactly as cheaply as a compact one - the
attack targets the carrier, and the carrier is identical. The accepted-exposure
posture, accepted by the owner on 2026-08-14, stands unaltered. The asymmetric
upgrade buys three
things and only three: forgery becomes impossible without the signing key even for
detection-capable parties, verification becomes possible with no MTN service in the
loop, and the compromise blast radius shrinks because the signing key is not needed
to detect. It buys nothing against removal, nothing against replay, and nothing
toward pixel provenance.

Additional stated exposures:

- **Chosen-image access.** Known input/output pairs give the residual directly;
  multiple marked versions of one cover separate the stable constellation from
  the payload-dependent part, exposing data-bin support by covariance and the
  coefficient-to-bit map by supervised regression. An equivalent
  detector/stripper is recoverable without the secret. `EmbedResult.PayloadDigest`
  (`verum.go:16`) accelerates this and is removed from the public result.
- **Compromise blast radius.** A leaked signal-epoch secret enables offline
  detection and targeted removal across that epoch; **in compact mode** a leaked
  frame key enables authenticated-frame generation, while in attested mode frame
  keys carry no such power and minting needs the BLS signing key. Both in one
  environment grants removal plus
  forgery - hence the role split. Rotation cannot protect published images.
- **Q75 survival is not removal resistance.** Q85/Q80 ladders, custom quantization
  tables, down-up-sample cycles, suppression of the public annulus,
  denoise/sharpen chains and sub-pixel bending are all available. The deliverable
  is an attack-success-versus-perceptual-damage curve, not a "JPEG floor".

## Known limitations

- Regions without a locally embeddable `P`-window cannot carry a frame; smooth sky,
  flat backgrounds and gradients are excluded by the 0.54-RMS arithmetic above.
- Token presence and token provenance are established; pixel provenance is not.
- Replay of a valid residual onto unrelated content validates. Inherent to a
  content-independent robust mark.
- **A single marked image is enough to locate the constellation.** Folding it mod
  `P` gives 14.5 dB of coherent gain and the sparse elevated bins are outliers in a
  public band; nulling them is perceptually cheap and needs no key. The design
  raises removal cost, it does not prevent removal.
- Corpus averaging within one epoch recovers a reusable template at up to 61.5 dB
  of gain at the 50,000-image epoch cap; epoch rotation is the entire bound.
- Heavy local warps, perspective, content-aware scaling and StirMark-style random
  bending desynchronize local windows; Fourier-Mellin recovers global RST only.
  The measured failure threshold goes in NOTICE.
- AI regeneration, diffusion inpainting and semantic re-rendering may rewrite
  pixels faster than the mark survives.
- Print/photograph cycles exceed `StrengthBalanced` margin.
- At 0.5x, P=192 runs at zero coding margin (one surviving codeword) and loses
  half its constellation, costing 3 dB of pilot gain and shortening the scale lever
  arm; below 0.5x the full frame does not survive. P=256 retains two copies.
- If Phase 0 selects the noncoherent fallback arm, P=192 carries one rate-1/3
  codeword spread across all four bands (18 symbols spare), with **no repeat copy
  and no 0.5x claim** - the one codeword spans all four bands, so 0.5x erases the
  portion of it that sits in bands 3-4 and there is no complete second copy to fall
  back on. Phase 0 may instead select rate 1/2 there if the measured FER is better.
- At P=192 the conservative halo bound leaves 12 spare pairs in band pair 1-2, a 2%
  margin against enumeration drift or a halo wider than the ±2 bound; the Phase 0/1
  halo measurement decides whether copy 2, and with it +3.0 dB, survives.
- P=128 is not supported; its removal is approved by the owner (2026-08-14).
- Lossy WebP output remains unsupported without CGO.
- Detection is materially more expensive than the pre-release implementation:
  ≈1.5 s single-core at E=1 for a compact-only detector at P=192, ≈1.86 s typical
  and ≈1.96 s worst case at P=256 in the default attested mode with blind try-both
  decoding, rising to ≈2.4 s at an eight-epoch ring, and ≈26 s for the forensic
  sweep. The ≤1.5 s target holds only for compact-only detection at E=1.

## Phase 0 - feasibility spike (gates everything)

1-2 weeks. Disposable code under `internal/spike/`, never shipped, deleted at
Phase 1. Fixed P=192, one profile, hardcoded keys, no key schedule, no API.

**Arms.** (a) sparse guarded constellation with additive keyed phase and coherent
data decoding; (a') the same carrier with noncoherent differential-energy data;
(b) dense tiled FM carrier as specified in v2, for comparison; (c)
invariant-domain payload - FM-magnitude or angular descriptor with cyclic search,
lower capacity.

**Frame-agnostic.** The spike measures carrier physics, which does not depend on
the authenticator. Both codeword lengths - 600 compact and 1,080 attested - are
carried as measured configurations so the FER numbers exist for each before Phase 3
commits to a codec.

**Corpus.** ≥20 real photographs spanning the five fixture classes: detailed
photos, screenshots/UI, portraits, gradients/smooth, dark images. **This corpus is
a smoke test.** Twenty images cannot establish a false-positive rate at any level
this design cares about; Phase 0's FP row is a sanity check and the binding FP
verification is Phase 6.

**Transforms.** JPEG Q75; rotations {7°, 17°, 45°, 97°}; scales
{0.5, 0.8, 1.0, 1.6}; crop-paste onto unrelated backgrounds; worst-case crop
phases (all offsets mod P at stride P/8).

**Measurements.** Sync ROC for marked versus unmarked windows; per-pilot complex
SNR `ρ` achieved at the visibility budget; pose error distributions; `τ` recovery
rate; measured soft-channel BER per modulation; stage-1 lattice SNR on pasted
patches; halo leakage width, which selects the binding halo bound.

**Go/no-go criteria** - an arm passes only if all gated rows hold:

| Criterion | Threshold | Status |
|-----------|-----------|--------|
| Per-pilot complex SNR `ρ` at the visibility budget, S=48 | ≥ 0.384 (−4.2 dB) | **gate** |
| Detection rate on embeddable P=192 windows at Q75 + 17° + 0.8x | ≥ 0.90 | **gate** |
| Pose error, 90th percentile | \|δθ\| ≤ 0.34°, \|δs/s\| ≤ 0.6% | **gate** |
| τ recovery within ±0.5 px per axis | ≥ 95% of decoded windows | **gate** |
| **Frame error rate, compact** at Q75 + 17° + 0.8x, real chain | ≤ 10% one-sided 95% upper bound, ≥30 independent images | **primary gate** |
| **Frame error rate, attested** at the same operating point | ≤ 10% on the same basis | **default-selection gate** |
| Raw soft-channel BER at the same operating point | ≈11% guidance | reported |
| Canonical SSIM / p1 local SSIM / PSNR at the operating amplitude | ≥ 0.995 / ≥ 0.985 / ≥ 44 | **gate** |
| Detection rate on embeddable windows at Q75 + 0.5x | ≥ 0.80 | **claim gate** |
| Sync ROC AUC, marked vs unmarked windows | ≥ 0.99 | reported |
| False positives on the 20-image corpus | none observed | smoke only |
| Stage-1 global-lattice recall on 192² pasted patches | measured | reported |
| Measured halo leakage width | measured | selects the binding halo bound |
| Realized `ProtectedAreaRatio` on the five fixture classes | measured | catches an unreachable assumed amplitude |
| Residual cap-violation budget from the p5 envelope | measured | feeds the Phase 4 quality gates |
| Out-of-halo gain-field leakage fraction | measured | `sinc²` is not band-limited; feeds halo-bound selection |

The **claim gate** row is scoped deliberately: failing 0.5x detection drops the
0.5x capability claim from README/NOTICE, it does not fail the project.

**How the FER gate is counted.** The unit of independence is the **image**, not the
window and not the transform: rotations, scales and recompressions of one photograph
are strongly correlated, so treating them as independent trials would inflate the
sample count without adding evidence. The gate requires **≥30 independent source
images**, balanced across the five fixture classes, and is stated as a **one-sided
95% upper confidence bound below 10%**, not as a point estimate. Zero observed
frame failures needs `n ≥ 29` to clear that bound (`1 − 0.05^(1/n) < 0.10`), so 30
images is the minimum that can pass on a clean run and gives a 9.5% bound; any
observed failure raises the required `n` accordingly.

**Why FER and not BER.** The effective rate with ≈15% self-signaled erasures is
`200/510 = 0.392`, whose Shannon crossover is 14.9% and whose practical
soft-Viterbi threshold is ≈11% - the r1 figure of 13% described a clean rate-1/3
channel this design does not have. More fundamentally, a BER gate imports
independence and Gaussianity assumptions that a screened, self-signaling,
band-erased channel violates, so a measured frame outcome is the only honest gate.
BER stays as engineering guidance for tuning.

For the same reason the two-copy combining arithmetic - raw 15% at
`Eb/N0 = 0.537` becoming `Eb/N0 = 1.074` and an effective 7.1% after +3.0 dB - is
an **independent-AWGN illustration only and is not a gate**. It shows the shape of
the benefit; it does not predict this channel.

The two FER rows differ in consequence, deliberately. The **compact** row is a
project pass/fail: if the 600-symbol codeword cannot clear 10%, the carrier does not
work. The **attested** row is a **default-selection gate**: failing it flips the
P=256 default to compact and makes attested an opt-in, but it does not fail the
project.

**Named outcome: the P=256 frame-mode default.** Phase 0 measures FER separately
for the 600-symbol compact and 1,080-symbol attested codewords. Phase 0 runs at
**P=192 only**, so the P=256 conclusion is an inference and the
reasoning is written down rather than assumed: P=192 attested is **strictly harder**
than P=256 attested - a single cross-four-band copy with no repeat, in a smaller
window with less processing gain, versus two complementary copies. So **P=192
attested passing implies P=256 attested passing**, while a P=192 attested failure is
inconclusive for P=256 and defers to Phase 6. Final P=256 confirmation lands in the
Phase 6 patch-floor calibration either way. If attested fails
the ≤10% gate at P=256 while compact passes, **the P=256 default flips to compact**
and public verifiability becomes an explicit per-tenant opt-in carrying a measured
robustness cost. This is a pre-declared outcome with a pre-declared consequence, not
a judgement call made after seeing the numbers, and it is recorded here so the
result cannot be quietly reinterpreted. If both fail, the failure is a carrier
problem, not a frame problem, and the escalation below applies.

If no arm passes, the local-window contract is retracted and the decision -
whole-image-only mark, invariant-domain presence-only token, or abandon -
escalates to the user. Phases 1-7 do not start before an arm passes.

## Phases 1-7

**Phase 1 - key schedule and carrier** (`internal/carrier/`)
- HKDF named-argument schedule with length-prefixed contexts; `payloadTagKey` and
  `frameMACKey` separated; exact DRBG input encodings documented.
- `Config.validate` enforces `SignalKeys` non-empty and ≤8, and the **total tried**
  frame-key set `|{ActiveKey} ∪ DetectionKeys| ≤ 16` **scoped per mode** - in
  attested mode frame keys are embed-only, so an attested-only deployment may
  configure none - each secret ≥32 bytes,
  `SignalGroupID` non-empty, and `MinPatchSize` ∈ {192, 256}. It enforces
  `Payload.Nonce` **length** (≥16 bytes) only - a library cannot verify that bytes
  came from a CSPRNG, so sourcing is a documented caller duty, stated in NOTICE.
- Keyed sparse constellation generator: additive keyed complex phase, minimum
  separation, enforced angular asymmetry, band-4 inner-two-thirds radial
  constraint, 4 equal-area radial bands at the normative six-decimal edges.
- Halo enforcement under both bounds; the measured leakage width from Phase 0
  selects which binds. Layout emits per-band-pair data counts so capacity is an
  output.
- Hermitian symmetry, DC/low-band suppression, separate `a_e` embed amplitude and
  `a_gate = 1.5·a_e` spectral-line gate.

**Phase 2 - pose and translation** (`internal/fmellin/`)
- Tapered real-input FFT magnitude, log-polar resample, phase correlation.
- Subpixel peak refinement, peak-ratio scoring, centrosymmetric branch.
- Coherent complex matched filter against the keyed pilot template; `τ` recovery
  by normalized cross-power over pilot bins.
- Joint `(θ, s, τ)` Gauss-Newton refinement against the coherent pilot likelihood;
  measured `√S` processing gain compared against the Phase 0 `ρ` figure.
- Synthetic pose tests asserting the section-2 accuracy targets and the absence of
  90°-family aliases.

**Phase 3 - frame and coded data layer** (`internal/spreadbits/`)
- Dual frame codec: 200-bit compact (96-bit token + 96-bit HMAC) and 360-bit
  attested (96-bit token + 256-bit BLS signature), selected by one flags bit; no
  CRC in either.
- BN254 BLS assembled per the §3b spec over gnark-crypto primitives: RFC 9380
  HashToG1 with the pinned SVDW/XMD/SHA-256 suite and DST, strict point decoding on
  signature and public key, G1/G2 orientation. **Published test vectors are a
  deliverable of this phase**, not a follow-up.
- Canonical signed-message serialization; 2-bit signing-generation ring with
  revocation reporting; `Signer` interface with a KMS-backed implementation.
- `FrameMode` config with the P=256-attested / P=192-compact defaults; blind
  try-both decoding plus `FrameModeHint`; early-reject-before-pairing rule.
- `cmd/verum-verify` skeleton with the narrow output contract.
- Rate-1/3 constraint-length-7 **tail-biting** convolutional encoder with soft
  Viterbi returning a single survivor; repetition baseline.
- Complementary band-pair copy layout with interleaving inside each copy - but the
  layout is **not universal**: the P=192 fallback arm has too few differential
  symbols per band pair and spreads one copy across all four bands instead. The
  encoder selects the layout from `(P, arm)`, it does not assume pairing.
- Pilot-based LLR estimator; global per-image data-bin screen.
- Pilot-noise-normalized coherent matched-filter LLRs, so screen-zeroed bins
  self-signal; no known erasure map is passed to the decoder, and raw observed
  magnitude is never used as a weight (see the reliability spec).
- Coherent soft-symbol modulation over guarded data pairs, plus the noncoherent
  differential-energy fallback selected by Phase 0.
- Capacity assertions matching the per-band-pair table for 192 and 256, under both halo bounds.

**Phase 4 - embed pipeline** (`embed.go`)
- Per-tile synthesis, per-occurrence `p5` Watson gain sampling, bilinear
  interpolation between occurrence centers, spatial compositing. No low-pass stage
  and no clamp; the deliverables are the **measured** cap-violation budget and the
  **measured** out-of-halo leakage fraction, both feeding the quality gates and the
  halo-bound selection.
- Embeddability map and `ProtectedAreaRatio` derived from the thresholded gain
  field.
- Minimum-robust-amplitude binary search, capped at 4 probes.
- Self-detection must decode and validate the frame authenticator (MAC or
  signature per mode); sync-only evidence fails. Balanced/Robust additionally
  self-verify a Q75 round trip and five crop
  phases (four half-period corners plus one keyed random).
- Quality gates: canonical 11×11 Gaussian SSIM, p1 local SSIM, PSNR, max delta,
  changed-pixel ratio, local RMS, spectral-line limit, smooth-region check.
- JPEG output for non-opaque input returns `ErrUnsupportedFormat`.

**Phase 5 - detect pipeline** (`detect.go`)
- Stages 0-4 as specified, with the signal key ring iterated on stages 0-2 and
  only the keyed correlation repeating per epoch.
- Binary `DetectResult` by default; `ForensicReport` behind `Forensic`.
- Byte-identical zero-value result on every failure cause; no
  failure-cause-dependent early exit within a stage.
- Estimated-inlier-fraction computation from sync residual support.
- Region clustering, per-epoch/key template cache, bounded memory, bounded
  concurrency, early exit on two independent validated regions.

**Phase 6 - corpus calibration and claims alignment**
- Composite fixtures: rectangular crops, irregular masks, pasted subjects,
  unrelated backgrounds, rotation, scale, JPEG sweeps.
- Patch-floor calibration for 192 / 256.
- Rotation sweep every 15°, dense near alias-prone angles.
- Scale sweep across the calibrated range, several resampling kernels, with the
  0.5x erasure budget verified directly.
- Candidate-stage recall for stages 0-2 against the **≥95% release threshold**.
- False-positive ROC over hostile negative classes: UI patterns, halftones, moiré,
  JPEG block grids, band-limited adversarial noise. Budgets are set by what each
  bound requires, not by convenience:
  - **≥1.3×10⁷ negative window trials** to place a 95% rule-of-three zero-event
    bound at 2.3×10⁻⁷ per window. At the 1.91 ms stage-2 cost (shared 1.69 +
    per-epoch 0.22 at E=1) this is **≈6.9 h single-core** - affordable, and it is
    the reason the budget is set here.
  - **≥30,000 negative images** to place the per-image bound at 10⁻⁴.
  - Thresholds calibrated on the max statistic over all windows, scales, lags,
    epochs and keys.
  - The operating point needs a per-trial FP of **1.068×10⁻¹¹** (see the T
    derivation), which is **4.33 orders** below what 1.3×10⁷ trials can verify
    directly. The threshold is therefore set from a parametric tail model of the
    correlation statistic under H₀, and the empirical trials **validate that model's
    tail only as far as 2.3×10⁻⁷** rather than validating the operating point. This
    gap is stated, not closed.
- README / NOTICE / CHANGELOG updated with measured numbers only.

**Phase 7 - adversarial review and release gates**
- **Single-image fold+null arm at N = 1**: fold mod `P`, locate elevated bins by
  outlier statistics without any key, null them, measure removal success versus
  SSIM damage. **Under the selected Public posture the attacker does not even need
  to implement the fold** - the published bundle detects the mark directly - so this
  arm measures the floor, not the ceiling, of removal cost. The deliverable is the
  curve, and the gate is **not** that the attack fails: it will not fail, and the
  exposure is already accepted on the record (2026-08-14). The gate is that
  **README, NOTICE and product claims match the measured curve**, confirmed by
  owner sign-off before v1 release.
- Corpus template-estimation at N = 1, 4, 16, 64, 256 images per epoch, with a
  fitted curve **extrapolated to the 50,000-image epoch cap**; deliverable is
  removal-success versus SSIM-damage curves at both the measured points and the
  cap.
- Chosen-cover attacks, known input/output pairs, same-cover multi-payload
  separation, known-frame-bits attacks, at log-scaled corpus sizes.
- Oracle-guided stripping simulation run against the *minimal* API, confirming
  the minimal result does not accelerate removal materially over blind attack.
- Band suppression, repeated recompression ladders, down-up-sample cycles,
  denoise/sharpen chains.
- Local random bending and perspective, with the measured failure threshold
  published as a limitation.
- Replay/transplant verification per the evidence model.
- Loop until claims match measurements and NOTICE reflects every limitation.

Required test classes:

Carrier and layout:

- `TestConstellationSeparationAndAsymmetry` - minimum angular/radial separation holds at 192 and 256, halos are disjoint, band-4 peaks respect the inner-two-thirds constraint, and the angular autocorrelation shows no 90°-family peak above threshold.
- `TestBandEdgesAndCounts` - the three interior band edges match 0.130000 / 0.165529 / 0.194679 to six decimals; enumerated per-band pair counts are 596 / 616 / 612 / 612 at P=192 and 1,088 / 1,070 / 1,090 / 1,078 at P=256.

- `TestCapacityLayoutMatchesBudget` - emitted per-band-pair counts match the capacity table within 2%; the encoder refuses frame/rate/copy combinations that exceed a band pair.
- `TestTailBitingCodewordLength` - 200 raw bits code to exactly 600 symbols and 360 raw bits to exactly 1,080, with no flush bits; the non-tail-biting 618-symbol compact variant is rejected at P=192.
- `TestAttestedFrameRoundTrip` - a 360-bit attested frame embeds, decodes and verifies against the public key across the standard transform set.
- `TestAttestedForgeryRequiresSigningKey` - holding every signal key, every detection key and the public verification key does **not** allow producing a valid signature over a **previously unseen** signed-message tuple; only the BLS private scalar does. Replay of an already-signed tuple is out of scope here and is covered positively below.
- `TestFrameModeCapacityFit` - the encoder accepts attested at P=256 under both halo bounds, accepts it at P=192 only as a single cross-band copy with the 0.5x claim disabled, and **rejects attested + noncoherent fallback at P=192 conservative** at every rate.
- `TestCompactAttestedCoexistence` - one blind detector handles both flag values in the same corpus without configuration, including a mixed-mode image set, with `FrameModeHint` unset.
- `TestFrameModeBitAuthenticated` - flipping the mode bit invalidates the signature, since the header is inside the signed message; there is no downgrade path.
- `TestFrameModeHintSkipsDecode` - a hint removes exactly one decode attempt and changes no verdict on correctly-hinted input.
- `TestSigningContextBinding` - a valid frame re-encoded under a different `P`, epoch or `signalGroupID` fails verification, closing configuration-context replay.
- `TestSigningKeyGenerationRing` - the 2-bit ID selects the pinned key directly with no trial verification; marks under an old generation still verify; a revoked generation verifies but reports `GenerationRevoked`.
- `TestStrictPointDecoding` - non-canonical, off-curve and identity elements are rejected for both signature and public key; **wrong-subgroup rejection is asserted on G2 public keys**, BN254 G1 being prime-order, and a small-subgroup G2 element that `PairingCheck` alone would accept is rejected.
- `TestHashToCurveVectors` - the published Phase 3 test vectors reproduce exactly, including the pinned DST and the clear-cofactor step.
- `TestEarlyRejectBeforePairing` - the header and point-decode checks run before any pairing, and measured pairings per negative image match the ≈0.5 expectation.
- `TestBundleCannotMint` - a holder of the full verification bundle cannot produce a valid signature over any **previously unseen** signed-message tuple.
- `TestBundleReplayReembed` - the positive counterpart: a bundle holder **can** decode captured signed frame bytes and freshly re-embed them into an unrelated image, and the result validates. This documents the accepted replay property rather than asserting it fails.
- `TestBundleManifestRequired` - `OpenBundle` rejects an unsigned manifest, one signed under the wrong root, and one whose contents were altered after signing; there is no code path that accepts raw caller-supplied verification keys.
- `TestRevokedGenerationNotVerified` - a signature under a revoked generation yields `Verified = false` in the default result, with the "valid signature under revoked generation" detail appearing only in `ForensicReport`.
- `TestGenerationIDsNeverReused` - the fourth retirement requires a `PayloadVersion` bump; the implementation refuses to recycle a generation ID.
- `TestStandaloneVerifier` - `cmd/verum-verify` verifies with no network access and no mtnai import; the test fails if the binary links either.
- `TestVerifySignatureBeforeExpected` - `Verify` rejects a bad signature as unauthenticated rather than reporting a payload mismatch, so failure ordering leaks nothing about the expected payload.
- `TestMinPatchSizeRejects128` - `Config.validate` accepts 192 and 256, maps 0 to 192, and rejects 128 with a clear error.

Pose, translation and decode:

- `TestTranslationRecovery` - `τ` recovered within ±0.5 px for all crop phases at stride P/8, across rotations and scales.
- `TestPoseAccuracyTargets` - `|δθ| ≤ 0.34°`, `|δs/s| ≤ 0.6%` at the 90th percentile on synthetic and real windows.
- `TestCoherentDecodeRequiresTau` - decoding with `τ` forced to zero fails, proving the translation stage is load-bearing.
- `TestCoherentMatchedFilterGain` - the complex pilot correlator achieves within 1 dB of the `√S` gain bound on synthetic windows, and degrades as predicted when pilot phase is randomized.
- `TestPilotSNRRequirement` - at the measured operating amplitude, per-pilot `ρ` and the resulting τ error distribution satisfy `σ_τ ≤ 0.2236 px` per axis.
- `TestFoldAllLagsDetection` - stage 0 detects at every origin offset mod `P`, not only at zero lag.
- `TestCentrosymmetricBranchResolved` - the 180° branch is enumerated and resolved by frame validation, not by the pose score.
- `TestDownscaleErasureBudget` - at 0.5x, bands 3-4 are treated as erasures and the rate-1/3 codeword still decodes, or the failure is recorded as a measured limitation.
- `TestFallbackLayoutNotPaired` - under the noncoherent arm at P=192 the encoder spreads one codeword across all four bands rather than assuming complementary pairing, and the build refuses to advertise a 0.5x claim for that configuration.
- `TestPilotBasedLLR` - reliability weights come from the pilot residual noise estimate; a screened bin sitting on a large host coefficient is *not* weighted as reliable.
- `TestGlobalScreenIsPerImage` - the data-bin screen is one image-level decision on the shared tile, not a per-occurrence mask.

Keys and frame:

- `TestKDFDomainSeparation` - `payloadTagKey` and `frameMACKey` differ, contexts are length-prefixed and unambiguous, no key derives from a raw secret.
- `TestSignalKeyRingRequired` - embed and detect require `SignalKeys`; a wrong signal secret yields no validated detection even with correct frame keys.
- `TestEpochRingDetection` - images from epoch E₀ still detect after the ring advances to E₁; cost scales ×E on signal stages only, frame-MAC checks stay O(K).
- `TestLayoutIndependentOfNonce` - two payloads under one key and epoch produce the *identical* constellation and data-bin map; only the token bits differ.
- `TestNonceRequired` - `Config.validate` rejects empty or sub-16-byte `Payload.Nonce` and the token changes when the nonce changes; CSPRNG sourcing is a caller duty and is explicitly not asserted here.
- `TestKeyCountCaps` - `Config.validate` rejects a total tried frame-key set above 16 or more than 8 signal keys, the counts the MAC union bound assumes.
- `TestFrameKeyContextEpochIndependent` - the derived frame MAC key is identical across epochs and patch sizes, so MAC checking stays `O(K)`.
- `TestMACLengthAndUnionBound` - the compact MAC is 96 bits at every supported `P` with no 128-bit variant; a randomized 10⁷-trial misdecode harness produces zero validations. For attested frames the same harness confirms zero pairing passes, the union bound being replaced by signature verification.

Detector and API surface:

- `TestMinimalOracleOutput` - the default `DetectResult` has no band, bounds, scores, pose or failure stage; `Forensic` is nil unless requested; identifiers are empty unless `Verified`.
- `TestUniformFailureOutput` - no-sync, partial, ECC failure, wrong key, MAC failure, both-decode failure, malformed signature point and malformed public key all return the byte-identical zero-value `DetectResult`.
- `TestPartialEvidenceRequiresTwoPilots` - partial evidence requires two spatially independent pilot matches or the strict likelihood ratio, and never sets `Verified`.
- `TestCoarseToFineCandidateRecall` - stages 0-2 pass **≥95%** of truly marked windows into stage 3 on the composite corpus. The threshold is fixed, not calibrated from the same run.
- `TestStrideCoverage` - stride `P/2` yields ≥56% worst-case overlap with an exactly-`P` region, and stage 3 refinement recovers regions the coarse grid straddles.
- `TestForensicSweepEquivalence` - the exhaustive sweep finds every region the default pipeline finds, plus the measured delta, at its published cost.
- `TestFoldedFastPath` - untransformed marked images resolve in stage 0 without entering stage 1.
- `TestScalePyramidMemoryCap` - one resample buffer in flight; oversized settings refused or clamped; peak RSS under 100 MB.

Embed, contract and quality:

- `TestEmbeddabilityContract` - detection succeeds for regions containing an embeddable window, is not claimed for smooth regions, and `ProtectedAreaRatio` matches the embeddability map.
- `TestSmoothPatchAmplitudeCap` - a constant patch at SSIM 0.995 yields watermark RMS ≤ 0.55 luma levels; no Q75 survival is claimed for it.
- `TestGainEnvelopeSpectrum` - the bilinearly interpolated gain field matches the `sinc²(fP)` triangular-kernel spectrum, first null at `1/P` and first sidelobe at −26.5 dB; the test **records** out-of-halo leakage rather than asserting a bound, since `sinc²` sidelobes extend indefinitely.
- `TestGainEnvelopeCapViolation` - measured cap violation across all five fixture classes, asserted against the Phase 0 budget rather than a derived bound, with p1 local SSIM as the backstop.
- `TestProtectedAreaGranularity` - `ProtectedAreaRatio` resolves at `P`, and a textured subject smaller than an occurrence is *not* reported as separately protected.
- `TestSelfSignalingErasures` - the decoder is never handed a screen position list; screen-zeroed bins are handled purely by pilot-noise-normalized coherent matched-filter LLRs, never by raw observed magnitude.
- `TestFrameErrorRate` - measured FER through the real encoder/screen/decoder chain at Q75 + 17° + 0.8x over ≥30 independent fixture-class-balanced images, asserted as a one-sided 95% upper bound below 10%, with the image as the unit of independence.
- `TestFullSurfaceStage2` - stage 2 maximizes over all 128×64 log-polar cells; a pose falling between any 8-sample grid is still found.
- `TestTotalFrameKeyCap` - `|{ActiveKey} ∪ DetectionKeys| ≤ 16` is enforced on the tried set, not on `DetectionKeys` alone.
- `TestCrossGroupFrameReplayRejected` - a frame minted under signal group A does not validate under group B even when the frame key is shared.
- `TestMinimumAmplitudeSearch` - the binary search terminates within 4 probes at the lowest amplitude satisfying both quality and detection.
- `TestSelfDetectionRequiresFrameAuth` - self-detection passes only on frame-authenticator validation (MAC or signature per mode); Balanced/Robust additionally require the Q75 round trip and all five crop phases (four half-period corners plus one keyed random).
- `TestCanonicalSSIM` - 11×11 Gaussian, BT.601 luma, frozen border and aggregation, cross-checked against reference vectors.
- `TestLocalQualityGates` - p1 local SSIM, local RMS, spectral-line limit and smooth-region check across all five fixture classes.
- `TestJPEGAlphaRejected` - JPEG output for non-opaque input returns `ErrUnsupportedFormat` without flattening.

Robustness corpus:

- `TestCompositeRegionDetection` - embed 1024², cut an embeddable region, paste onto unrelated background, detect and match key, epoch and token.
- `TestIrregularMaskComposite` - subject-shaped alpha mask; succeeds above the inlier-fraction floor and fails below it.
- `TestCropPhaseSweep` - every crop offset mod `P` at stride P/8.
- `TestRotationSweep` - every 15° from 0 to 345°, dense near 45°, 90° and 180°.
- `TestScaleSweep` - calibrated range with several resampling kernels.
- `TestCombinedTransformSweep` - crop + rotate + scale + JPEG in one pipeline.
- `TestJPEGSurvival_Q75` - Balanced and Robust Q75 round-trip survival.
- `TestFalsePositiveROC` - hostile negative corpus, max-over-trials calibration, per-image confidence intervals, **≥1.3×10⁷ negative window trials across ≥30,000 negative images**, matching the Phase 6 budget.

Adversarial release gates:

- `TestSingleImageFoldNull` - fold one marked image mod `P` with no key, locate elevated bins by outlier statistics, null them, and record removal success versus SSIM damage. Asserts the documented weakness, not immunity.
- `TestCorpusTemplateEstimation` - N = 1/4/16/64/256 images per epoch with a fitted extrapolation to the 50,000-image epoch cap; asserts NOTICE publishes the cap figure, not just N=100.
- `TestChosenCoverAttack` - known input/output pairs and same-cover multi-payload sets; asserts the published exposure statement, not immunity.
- `TestCopyAttackReplay` - a residual transplanted from A onto unrelated B *does* validate as A's token, proving the documented evidence-model boundary.
- `TestOracleGuidedStripping` - an attacker driving only the minimal API does not reach removal materially faster than blind attack.
- `TestBandSuppressionAndRecompressionLadder` - measured survival against annulus suppression, Q85/Q80 ladders and down-up-sample cycles.
- `TestLocalBendingThreshold` - records the bending magnitude at which detection fails, published as a limitation.
- `TestPayloadVersionReset` - `PayloadVersion == 1`, a version-2 frame header is **rejected**, the pre-release tile-grid format is rejected, and NOTICE documents the abandonment.
- `BenchmarkEmbedDetectCost` - embed, default detect and forensic sweep costs at 1024². Results guide optimization only; they never lower quality, security or robustness thresholds.
